Where the screen’s numbers come from

Collection and dashboard access use different paths. The diagram shows the optional device-collection path and the authenticated read path; organizer-prepared workshop collection can use a separate configured path.

Collection: client → stored observations

Claude Code and Codex export supported signals to a local Collector. A registered device sends them through the authenticated ingestion gateway and central Collector to ClickHouse. The device credential is separate from browser login.

Reading: signed-in user → dashboard result

Organization login supplies the configured role. The API applies time, client and supported filters before returning usage and diagnostic views. Read the cost basis and coverage: a screen can contain a known subtotal or an unavailable signal.

Your first visit

  1. Open your organization's dashboard and sign in. Ask the organizer for its address and access. The public site you are reading is the documentation. See accounts and permissions.
  2. Choose a client and time period. Start with all enabled clients and a period containing recent work. Check the displayed time zone and whether data has arrived.
  3. Read Overview. Compare known cost, observed tokens, sessions and users. Read partial or unavailable labels before drawing conclusions.
  4. Choose the menu that matches your question. Use the map below, then follow its step-by-step guide. Common views compare clients; Claude detail exposes additional Claude-specific views.
  5. Drill down and share the relevant view. Inspect a model, user or task where supported. Keep the selected period and filters in mind when exporting or sharing.

Read a number before interpreting it

  • Known cost is not an invoice. Claude reported spend and supported list-price estimates retain their cost basis. Missing prices can make a subtotal partial.
  • Unavailable is different from zero. Observed token subtotals, complete token components and diagnostic coverage answer different questions. A positive total does not establish complete collection.
  • Activity is an observation. Sessions, tools and cost ratios do not establish employee performance, saved hours or causal productivity.

Set the period and use the charts

Use UTC calendar dates or the picker’s 날짜·시간 (date and time) tab for exact browser-local start and end times. The end is exclusive. Read the displayed effective interval: server rollups and ingestion grace still apply.

Drag supported time-series charts to narrow the page period and use the reset control to return. In user detail, the task list follows that range; clicking a point selects one bucket. Categorical charts do not provide time-range selection.

Follow a user into the work

Open Users, select a user and inspect the task list for the selected period. A task opens Task Trace: main and subagent lanes, calls, known costs, token context, models and available session environment.

Tracing is optional. Claude interactions and Codex traced turns have different evidence; missing calls, attributes or prices remain unavailable. Task lists and detail have explicit limits.

Separate task usage from diagnostic traces

The Codex diagnostic Trace tab in Analytics is a separate preview from Task Trace. It shows spans and their available metadata; diagnostic metrics and spans do not add usage or cost to completion-log totals.

Keep the dimensions separate

Client identifies Claude Code or Codex; backend describes the provider path; model identifies the model. A model name alone does not identify the emitting client.

Claude’s bedrock / enterprise comparison uses inferred session channels. These are separate from dashboard login and do not provide a Codex enterprise A/B comparison.
