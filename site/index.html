From a user to a Task Trace

  1. Choose your time range and client filters. The date picker’s Date and time tab accepts exact browser-local times. Open Users, then select a user to open 사용자 상세 (user detail).
  2. The task list immediately shows up to 20 tasks in the overview’s effective range. Drag across the user’s usage/cost trend to narrow the page and task list together. A point click selects one bucket; the reset control restores the full period. Sort by tokens, cost, subagents or duration. Select a workflow badge to show only that run's tasks.
  3. Select a task to open 작업 상세 (Task Trace). Read its tokens, cost basis, LLM calls, subagents and observed duration.
  4. Click a timeline bar to inspect that call or tool. Select a row in 모델별 호출 (model calls) to highlight matching LLM bars; select it again to clear. Press Escape or 닫기 (close) to close.
ViewHow to read it
Agent lanesThe main session appears first, followed by observed subagents. Darker LLM bars indicate larger input context; gray marks are tools, red marks are permission waits, and dashed lines connect observed agent spawns.
Cumulative costLane colors stack known call costs. Hover to inspect a point in time. Codex completions without a matching span can contribute to the task total without appearing in the band.
Selected spanInspect available model, token components, cost basis, timing and tool or permission metadata. Raw prompts, commands and paths are not shown.
왜 많이 썼나 (why it cost so much)Data-backed rules explain cache-read share, context growth, lane cost share, expensive calls, retries or permission waits when their inputs are available. The panel then lists each model's calls, known cost and share of the cost.
Model callsCompare model and call source by lane, call count and known cost. Highlighting a row changes timeline emphasis, not the totals.
Session environmentMCP servers by latest status, loaded plugins with skill, agent and command counts, and the first call's input context. OpenTelemetry does not report tool-definition counts or sizes.

Claude tasks represent interaction spans; Codex tasks represent traced turns and use linked completion logs for tokens and estimated cost. Codex currently has one main lane; subagent counts are not collected. Trace collection is optional, so this task list is a subset of dashboard activity. Trace retention is 90 days; older trend buckets cannot open a task list.

Inspect Codex diagnostic traces

With Codex selected, open Analytics and choose the Trace tab in Codex detail. Expand a Trace to inspect spans, parent IDs, models, tools, duration and status, or export the span table as CSV.

This preview shows the latest 50 traces and at most the latest 200 spans per trace. Its statistics describe displayed spans. A model filter includes only spans carrying model attributes. Long or conflicting traces can withhold duration and error totals.

Diagnostic spans do not add usage or cost to the dashboard. The Task Trace above links Codex completion logs to turns; the Analytics Trace tab is a separate diagnostic preview. Chat's reasoning and SQL steps are a separate display again.

Choose the time window and resolution

Open the period picker and select Date and time to enter the start and end down to seconds in your browser time zone. The end time is exclusive. Shared links retain the selected mode and UTC bounds; calendar-day mode still uses UTC dates.

Selected windowCost and Trends controls
Up to 24 hours10 minutes, 30 minutes, hourly, daily or weekly. A one-day view starts at hourly resolution.
More than 24 hoursHourly, daily or weekly. A two-day view does not offer ten-minute resolution.

Read the returned interval and effective time bounds. Exact input does not change ingestion grace, server quantization or historical rollup precision. In unit-economics charts, dashed segments connect observed endpoints across unavailable buckets; they are visual guides, not measured values.

Keep the dimensions separate

Client identifies the emitting application. Backend describes the observed or inferred provider path. Model identifies the model. A model name alone does not identify the coding client.

The Claude bedrock/enterprise comparison is an inferred session-channel view. It is separate from dashboard login and is not a Codex enterprise A/B comparison. One user can appear in multiple channels.

Analytics can answer additional questions through the guarded, read-only query path when enabled. Its availability depends on role, model access and deployment configuration.
