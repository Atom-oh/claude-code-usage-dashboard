Install the device Collector

Connect an existing Claude Code and Codex installation on macOS or Linux, including EC2, through a device-specific ingestion token.

Updated October 24, 2026 · Describes source behavior; verify your installed revision.

Choose your installation path

EnvironmentAction
Personal macOS or Linux machineFollow the package setup below. Python 3.9+, outbound HTTPS to GitHub and the dashboard, and installed coding clients are required.
Existing device-token packageRegister a replacement token and rerun installation with the same attribution ID.
Legacy personal macOS CollectorThe current installer recognizes the supported legacy service and asks before migrating it.
Legacy Linux or unknown serviceFollow the owner's manual migration procedure before installing.
Organizer-prepared Workshop Studio EC2Use the prepared clients and Collector. Do not install a second Collector or register an individual device token.

Packages support macOS/Linux on amd64 and arm64. The installer downloads Collector 0.163.1 from the official release and checks pinned SHA-256 values. Archives contain no binary or credential.

Download and run

  1. Sign in to your dashboard as an editor (analyst) or admin and open Collector installation. Viewer/demo users cannot download packages or register devices.
  2. Select your OS, download the archive and register a device. Keep its one-time token available until setup completes.
  3. Move the archive to the machine running the clients. Open a terminal in its download directory and confirm python3 --version is 3.9 or later.

macOS

tar -xzf ccdash-collector-darwin.tar.gz
cd ccdash-collector

Linux / EC2

tar -xzf ccdash-collector-linux.tar.gz
cd ccdash-collector
sudo loginctl enable-linger "$USER"

Run only your platform's commands. If the browser already extracted the archive, enter its directory. On Linux, reconnect if the user service manager was unavailable. Run the installer as your normal user.

Set the telemetry identity

Use the attribution ID your organization expects, preserving the existing ID when migrating. Replace the example endpoint with the command shown by your dashboard.

(
  printf 'Telemetry user ID/email: '
  IFS= read -r ccdash_user_id
  if [ -n "$ccdash_user_id" ]; then
    python3 install.py install \
      --endpoint 'https://dashboard.example.com/api/ingest' \
      --user-id "$ccdash_user_id"
  else
    printf '%s\n' 'Enter a nonempty telemetry user ID/email before installing.'
  fi
)

Paste the device token at the hidden prompt. For automation, --token-file accepts an existing regular file owned by your user with mode 0600. Do not put the token value in command arguments.

The token owner is not automatically written into telemetry as an SSO email. --user-id is client-provided attribution, not verified identity. A fresh installation otherwise defaults to the local login name.

The installer validates both client configurations, preserves model/provider/login settings and creates private backups. Custom CODEX_HOME or CLAUDE_CONFIG_DIR layouts need manual configuration.

Restart Claude Code and Codex after setup. To include recognized Codex backend provenance, use:

python3 "$HOME/.local/share/ccdash-collector/launch-codex.py"

Direct Codex launches still collect, but can lack backend provenance. Unknown/custom providers and profile or project overrides can remain unknown.

Migrate an existing Collector

The supported personal macOS legacy service is com.ccdash.otelcol, using ~/.otelcol/config.yaml. Close the coding clients and let the old queue drain before running the current installer.

  1. The installer verifies the service and prompts for migration.
  2. Confirmation permits the service transition and replacement of legacy Claude telemetry settings and old telemetry authentication headers.
  3. Settings are backed up, the old LaunchAgent is disabled, and the device Collector is started. Failed installation attempts restore the previous state; recovery failures report the private backup directory.

The old queue stays in ~/.otelcol and is not imported. Do not delete it during migration. Unknown listeners are not stopped automatically; ports 4317, 4318 and 13133 must belong to the supported service or be available.

A package reporting local Collector port is occupied; migrate the existing service first predates the guided migration. Download the current package. For unmanaged Claude telemetry outside the recognized legacy service, review the old destination before using --replace-claude-telemetry.

Use the complete installer guide for Linux migration, recovery and conflict-specific commands.

Confirm receipt and manage devices

After restarting the clients, perform a small amount of work, refresh the device list and check a recent dashboard time window with the intended user filter.

  • Local health and lastSeenAt indicate stages of delivery, not database persistence or complete cost telemetry.
  • Device tokens expire 30 days after issuance. Revoke lost or unused devices; cached validation on another replica can remain valid for up to ten seconds.
  • Browser logout or group removal does not revoke device tokens. Include explicit device revocation in offboarding.
  • macOS uses a per-user LaunchAgent while logged in. Linux uses a user systemd service; linger enables persistence across logout and reboot.
python3 "$HOME/.local/share/ccdash-collector/install.py" uninstall

Uninstall removes the managed service and local token. Revoke the device in the dashboard too; client settings, queues and private backups need separate review.

Workshop provisioning is a separate path

Organizers can prepare EC2 clients and the existing password-based ingest path centrally. Participants use that prepared environment. The device package accepts device tokens, not a ClickHouse password.

The repository's user-data.sh requires deployment inputs and secret provisioning; it is not a generic command participants can run unchanged.
