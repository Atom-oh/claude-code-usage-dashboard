Claude Code + Codex · ドキュメント

収集とクエリのパイプライン

専用のインストール環境では、クライアントのテレメトリ、範囲を制限した取り込み経路、ClickHouse ストレージ、認証付きダッシュボードを組み合わせます。

2026年11月14日更新 · ソースコードの動作を説明しています。インストール済みのリビジョンをご確認ください。

ユーザー、タスク、spanを関連付ける

ユーザー詳細では、正確なテレメトリ ID とトレンドのバケットを選択します。/api/users/tasks はそのバケット内で開始したタスクを一覧表示し、/api/users/tasks/detail は選択したタスクのレーン、span、根拠に基づくコストの説明を返します。

クライアントタスクとタイミング使用量とコスト
Claude Codeinteraction spanがタスクと所要時間を特定します。LLM、ツール、権限待ちの各spanでタイムラインを構成し、観測されたエージェント ID でレーンを構成します。LLM spanのトークンを使用します。利用可能な場合はログから結合した報告済みリクエストコストを、そうでない場合は該当する料金計算を使用します。表示される算定根拠が混在することがあります。
Codex会話 ID と一意のターン ID を持つターンがタスクを特定します。所要時間は観測されたspanの時間幅です。メインレーンのみ利用できます。ターンの時間範囲に紐づく、使用量を含む一意の完了ログからトークンと AWS のリスト価格による推定額を取得します。サンプリングされたspanには、表示用に対応する完了値を割り当てます。

Codex のタスク使用量は、紐づいた完了レコードの表示であり、別の会計情報源ではありません。未紐付けの完了は別途報告されます。一致するサンプリングspanがない呼び出しは、累積コスト帯に含まれない場合があります。Analytics Trace のプレビューは診断spanを独立して読み取ります。

タスク詳細のクエリでは、許可リストにあるメタデータを選択します。UI は ID をマスキングし、生のプロンプト、コマンド、パスを表示しません。この表示ポリシーは API アクセス制御を提供するものではありません。トレースデータの保持期間は90日で、使用量のロールアップとは別に管理されます。

任意のデバイス経路では /api/ingest/v1/{logs,metrics,traces} を使用します。ブラウザーのセッション Cookie では取り込みを認可できません。ClickHouse への書き込み認証情報は中央 Collector が保持し、PC には失効可能なデバイス認証情報を付与します。

主催者が準備したワークショップ環境には、別途設定済みの収集経路があります。移行せずに、デバイス用パッケージを準備済みの Collector に重ねて導入しないでください。

取り込みの信頼境界と制限

シグナルの意味を保つ

シグナル解釈
Claude のカウンター系列の識別情報、累積または差分の時間性、ベースライン、リセットを考慮します。累積エクスポートを使用量として合算しないでください。
Codex の完了ログ完全な識別情報を使って重複を排除し、使用量を含む完了を一度だけ料金計算します。ストリームの中間レコードを別の使用量合計に加算しません。
Codex のメトリクスとトレース診断情報として使用します。トークンやコストの観測値を完了ログの使用量に加算しないでください。
キャッシュトークンと推論トークン定義されている場合は、入力または出力の内訳として扱います。これらを標準合計に再度加えると、使用量を二重に数えることになります。
根拠の欠落または制限既知の小計は部分データのフラグを付けて保持します。影響を受ける厳密な比率は算出せず、その理由を示します。欠落はゼロを意味しません。

データの境界 · Codex の可観測性

クライアント、バックエンド、セッションチャネル

収集と API のルーティングでは、シグナルを送信したクライアントを識別します。プロバイダーの由来情報とモデルの根拠はバックエンドの分類に使用します。モデル ID だけではクライアントを特定できません。

Claude のセッションチャネル分類では、bedrock、enterprise、unknown を区別します。観測された Bedrock モデルの根拠と、組織またはモデルのフォールバック規則はセッション単位で適用されます。この分類はダッシュボードユーザーの SSO ロールではありません。

リージョン別・地域別の Bedrock モデル ID と、単独のプロバイダー ID は、料金計算とバックエンドの判定ロジックで正規化されます。すべてのモデル ID に価格があると仮定せず、未対応のスコープと不明な価格をそのまま保持してください。Codex にはエンタープライズの A/B 行はありません。

バックエンド料金計算の決定

合計を変えずにクエリ処理を減らす

  • view=cost は、共有の概要画面で範囲を限定したコストプロファイルを選択し、未使用の診断情報を省略します。
  • profile=effort は Codex のログのみの詳細を選択し、関連しないメトリクスやトレースのクエリをスキップします。
  • Codex のログ集約では、転送前に ClickHouse で完全な識別情報を持つイベントをまとめます。集約ファミリーの制限は表示されます。
  • Single-flight キャッシュと受付数の制限により、フィルターの識別情報、期限、過負荷エラーを維持しながら、繰り返し発生する処理を共有します。

これらの仕組みは処理量を減らしますが、同時接続ユーザー140人に対するキャパシティを保証するものではありません。対象のインストール環境で、代表的なフィルターの多様性、キャッシュが空の状態のトラフィック、取り込み、クエリのレイテンシを測定してください。

コストクエリのパフォーマンス

ダッシュボードとデバイスへのアクセス

OIDC は署名済みの ID を検証し、明示的なグループ値を viewer、analyst、admin に割り当てます。認可された閲覧者は、インストール環境全体のテレメトリを読み取れます。これは従業員ごとに行を分離する仕組みではありません。

デバイストークンはテレメトリの取り込みとインストーラーパッケージのダウンロードを許可しますが、ブラウザーへのアクセスは許可しません。各トークンは個別に所有され、期限切れまたは取り消しとなります。テレメトリの帰属情報はクライアントから提供されます。SSO セッションやトークンの所有権だけで、テレメトリのメールアドレスが自動的に認証されるわけではありません。

個人情報のマスキングは表示機能であり、API アクセス制御ではありません。収集フィルターは既知のコンテンツフィールドを除去しますが、対応対象のメタデータに任意の形式で含められた秘密情報は検出できません。

SSO の設定とセッションの更新 · Collector のインストール

デプロイの境界

ダッシュボードイメージにはWeb UIとAPIが含まれます。ClickHouse、そのスキーマ、OTel Collectorは、すべてのプラットフォームで別コンポーネントです。現在のComposeファイルにはCollectorが含まれず、EKS Terraformは既存のクラスター依存関係を再利用します。ECS/EC2ではインフラストラクチャ、認証情報、ネットワーク、プローブ、永続化の設定をレビューして用意する必要があります。Lambdaではアプリケーションをランタイムに適応させる必要があります。

必須コンポーネント · ホスティング方法の比較

スキーマのライフサイクル、アプリケーションイメージ、Collectorポリシー、ランタイムの選択肢は、それぞれ独立したデプロイ状態を持ちます。ビルドやTerraformの検証に成功しても、稼働中のロールアウトや移行が完了したことにはなりません。
