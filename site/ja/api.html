Task Trace API · 診断Trace API

認証

OIDCモードでは、テレメトリAPIはセッションCookieを使用します。未認証のAPIリクエストは、authentication_requiredとログインURLを含むJSONの401を返します。セッションを使う変更系リクエストには、設定済みのOriginと権限が必要です。

Basicモードでは、設定済みの認証情報が両方必要です。未認証のローカル開発は明示的に有効化する必要があります。パスワード設定が空でも、本番環境のログイン方式にはなりません。デバイス取り込みには、独自のBearerトークンによるゲートがあります。

GET /api/sessionは、ロール、権限、短期のexpiresAtを返します。任意のrefreshExpiresAtは、ログインの絶対期限です。IdPの生トークンは決して返しません。

時間とフィルター

パラメーター仕様
from, toタイムゾーンを含む ISO 8601 形式を使い、from < to を指定します。デフォルトの範囲は2日間、デフォルトの上限は90日です。デプロイ設定で変更できます。
client共有概要では all、claude、codex を指定できます。無効になっているソースは拒否されます。
backendクライアントビューでは all、bedrock-mantle、bedrock-runtime、anthropic、unknown を指定できます。
user, model既存の部分一致フィルターです。モデルの正規化と ID の式はエンドポイントによって異なります。
userExact, modelExact共有概要では、詳細表示のための行 ID 完全一致に使用します。返された applied_filters を確認してください。タスクルートには userExact が必須です。Codex insights で userExact が使えるのは profile=tools の場合だけで、modelExact は常に拒否されます。
intervalHoursラップされたルートでは、有限値を (0,744] の範囲で指定する必要があります。共有概要では、上限付きの1時間未満の解像度をサポートします。実際の bucket_hours と effective_range を確認してください。
groupClaude の推定セッションチャネルです。送信元のクライアントでも、SSO の認可グループでもありません。
projectエンドポイント固有であり、共通フィルターではありません。指定する前に API リファレンス全文を確認してください。

Cost/Trends で10分と30分を選択できるのは、時間範囲が24時間以内の場合のみです。それより古い範囲では1時間単位のロールアップが使われます。任意の細かい間隔をリクエストした場合、サポートされているネイティブのバケットに切り替わることがあります。

ブラウザーのピッカーでは、ローカルの日付と時刻を秒単位で指定できます。共有リンク向けに、ISO 形式の from/to 境界値と、UI 専用の rangeMode=time マーカーがシリアライズされます。このマーカーは API フィルターではありません。有効な境界値は、引き続き各エンドポイントの量子化、取り込み猶予、ロールアップのルールに従います。

共有クライアントとコストのエンドポイント

エンドポイント用途
GET /api/clients/overview合計、クライアント・モデル・ユーザー別の内訳、時系列、カバレッジを返します。任意のmodelTime=1を指定すると、モデル別の時系列も返します。
GET /api/clients/overview?view=cost同じコスト、トークンカバレッジ、母集団、範囲を返し、使用されないプロジェクト・ツール・運用診断を省略します。省略されたフィールドはゼロを意味しません。
GET /api/clients/token-economics有効期間とその直前の期間における、コスト方程式、要因分解、ユニットの推移、モデルの経済性、成果コスト、代表的なユーザー。移行 010 のバックフィル後にオペレーターが SESSION_TURNS_READ_FROM を設定するまで、値は利用できません。
GET /api/codex/insightsCodexの完了効率に加え、ログ、メトリクス、Traceの診断情報を返します。
GET /api/codex/insights?profile=effortコスト・使用量ビュー用のログのみの詳細です。メトリクスとTraceのカバレッジはnot_requestedです。
GET /api/cost/summary, /by-model, /by-user-model従来のClaude専用コストルートです。複数クライアントの合計として扱わないでください。

モデルごとのユーザー比率は、既知のユーザーコストを、選択したモデルの既知コスト小計で割って算出します。価格が不明な場合はその旨が示され、不明またはゼロの分母ではパーセンテージは返されません。

Codexの記録済み完了効率

completion_usageは、使用量を含む重複排除済みの完了ログを表し、basis="recorded_completions"を指定します。選択した時間範囲内のすべてのHTTP試行やセッションで、テレメトリが完全に記録されていることを示すものではありません。

フィールド分母と範囲
cache_hit_rate, cache_write_share記録済み完了内の正規化された入力トークンに対する、検証済みのキャッシュ読み取り・キャッシュ書き込みサブセットの比率です。
reasoning_shareこのコホートにおける正規化された出力トークンに対する、検証済みの推論サブセットの比率です。
tokens_per_completion正規化されたトークン数を記録済み完了数で割った値です。観測されたトークン小計を、欠落している正規化済みの構成要素の代わりにはできません。
cost_per_completion既知の完了コストを記録済み完了数全体で割った値で、部分的な価格情報であることも示されます。
cost_per_identified_session会話IDがある完了のみが、コストの分子と一意なセッション数の分母の両方に含まれます。
unidentified_completions別途集計され、識別済みセッションあたりのコストには含まれません。
completeness使用量・セッションの根拠の欠落、集約ファミリーの制限、未完了のトークン情報、利用可能な時間範囲全体のリクエスト数・セッション数を報告します。

構成要素の欠落、あり得ないサブセット、ゼロの分母、価格がすべて不明な場合、または使用量が制限されている場合でも、nullになることがあります。時間範囲全体に対する既存のHTTPリクエスト数・セッション数の比率には、引き続きより厳格な条件が適用されます。UIでは展開可能なセクションに表示されます。

Collector とデバイスの API

エンドポイント仕様
GET /api/collector機能の状態、設定済みの公開取り込みエンドポイント、バージョン、プラットフォーム、トークンの有効期間、installScriptUrl。
GET /api/collector/devices所有者に紐づくデバイス。1ページあたり最大50件。返されたカーソルはそのまま使用します。
POST /api/collector/devicesname と platform（darwin または linux）を指定して登録します。トークンは一度だけ返されます。
DELETE /api/collector/devices/:id所有するデバイスを失効させます。
GET /api/collector/package/:platform認証済みダウンロード。認証情報は埋め込まれません。
GET /api/ingest/install.shデバイス取り込みが設定されている場合に、公開インストーラースクリプトを提供します。帰属情報とトークンをターミナルで入力するよう求めます。認証情報は含みません。
GET /api/ingest/package/:platformdarwin または linux 用の、デバイスベアラー認証済みアーカイブ。デバイスごとに1時間あたり10回までダウンロードできます。ブラウザーセッションも埋め込みトークンも使用しません。
POST /api/ingest/v1/{logs,metrics,traces}デバイスのベアラートークンのみを使用します。OTLP JSON/protobuf、最大2 MiB、コンテンツ圧縮なし。

管理操作と手動の /api/collector/package/:platform ダウンロードには OIDC collector:manage（アナリスト／管理者）が必要です。閲覧者／デモのアクセス権ではデバイスを管理できません。インストーラースクリプトとデバイストークンを使うパッケージルートは、別の取り込み経路を使用します。デバイスのエンドポイントでは利用範囲のフィルターを使用しません。レスポンスとダウンロードは no-store です。

ヘルスチェックとエラー

/healthzは稼働確認用、/readyzはレディネス判定用です。保護された/api/health/dataは、取り込みデータの鮮度を報告します。プロセスが稼働中でも、テレメトリが最新であるとは限りません。

形式が不正なフィルターは、クエリの実行前に失敗します。更新サービスで障害が発生すると、Retry-After: 5を伴う503が返ることがあります。認証情報が期限切れまたは無効な場合は、ログインが必要です。クエリ数の上限に達すると、データベース処理が無制限に増えるのを避けるため、リクエストが拒否されることがあります。

ユーザータスクと Trace API

ユーザー詳細では、デフォルトで概要の有効期間が読み込まれます。グラフをドラッグするとページとタスクリストが更新され、ポイントをクリックすると1つのバケットが選択されます。概要のリクエストが保留中または失敗した場合、古いタスクリストを最新のものとして表示しません。

セッション認証済みのテレメトリーアクセスを使用します。userExact は、リクエストされた時間範囲内でタスクのテレメトリー所有者を選択します。ダッシュボード閲覧者が自分自身のテレメトリーだけを閲覧できるように制限するものではありません。

エンドポイントリクエストとレスポンス
GET /api/users/tasksuserExact と、選択した範囲の from/to が必須です。client、backend、Claude 専用の group、sort=tokens|cost|subagents|duration は任意です。最大20件のタスク、unattached_codex、クライアントごとの coverage、partial=true を返します。Claude 専用の workflowRunId または workflowName を指定すると、リストを1つのワークフロー実行に絞り込みます。
GET /api/users/tasks/detailリスト行の id、userExact、同じ範囲の境界値が必須です。task、lanes、spans、truncated、span_total、why を返します。存在しないタスクと、所有者／範囲が一致しない場合は、どちらも404を返します。Claude のタスクでは、セッションの MCP サーバーと読み込み済みプラグインを含む environment も返されます。
  • 両方のルートで team は拒否されます。返されたタスク ID はそのまま渡してください。無効になっているクライアントや形式が正しくない ID は拒否されます。
  • Claude のコスト順ソートでは、観測トークン数が最も多いタスク100件を候補プールとして順位付けします。sort_candidates.limited を確認してください。このプール外にある高コストのタスクは含まれない場合があります。Codex のターンはソート前にコストを計算します。
  • 詳細で返されるスパンは最新のものから最大5,000件です。切り詰められた Claude の詳細では、タスク全体およびレーンの合計、モデル、why は返されません。Codex の完了記録から算出したタスク合計はスパンの切り詰めに左右されませんが、切り詰められている場合、オーバーレイでは KPI 行とコスト帯が非表示になります。
  • スパン属性は許可リストで制限されています。トークンの内訳、コスト、タイミング、サブエージェントの根拠が欠けている場合、その情報は利用不可のままです。トレース収集は任意のため、タスクのレスポンスは常に部分的です。

Codex診断Traceのプレビュー

既定のGET /api/codex/insightsプロファイルには、traces、spanのレイテンシ集計、coverage.tracesが含まれます。最新のTraceを50件返し、各Traceにつき最新のspanを最大200件返します。この上限は、Task Trace詳細の5,000-span上限とは異なります。

統計は表示されているspanを対象とします。モデルフィルターが適用されるのは、モデル属性を持つspanだけです。切り詰めやspan識別子の競合がある場合、Trace単位の所要時間・エラー統計や詳細が返されないことがあります。メトリクスまたはTraceで観測されたトークンが、完了ログの使用量やコストに加算されることはありません。

effort、tools、performanceの各プロファイルはTraceを照会しません。カバレッジがnot_requestedでも、収集されていない証拠にはなりません。userExactを受け付けるのはprofile=toolsの場合だけです。Codex insightsのすべてのプロファイルでmodelExactは拒否されます。
