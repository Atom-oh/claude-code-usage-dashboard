Task Trace API · 诊断 Trace API

身份验证

在 OIDC 模式下，遥测 API 使用会话 Cookie。未通过身份验证的 API 请求会返回 JSON 401，其中包含 authentication_required 和登录 URL。不安全的会话请求必须包含已配置的 Origin，并且调用方须具有相应权限。

Basic 模式要求同时提供两项已配置的凭证。允许未经身份验证的本地开发需要显式启用；空密码配置不能用作生产环境登录模式。设备数据摄取使用独立的 bearer token 验证机制。

GET /api/session 会返回角色、权限和较短时限的 expiresAt；可选的 refreshExpiresAt 表示绝对登录截止时间。接口不会返回 IdP 原始令牌。

时间和筛选条件

参数接口约定
from、to使用带时区的 ISO 8601 格式，并确保 from < to。默认时间范围为两天；默认上限为 90 天。部署设置可以更改这些值。
client共享概览：all、claude 或 codex；已禁用的数据源会被拒绝。
backend客户端视图：all、bedrock-mantle、bedrock-runtime、anthropic 或 unknown。
user、model现有的部分匹配筛选条件。模型规范化方式和身份表达式取决于端点。
userExact、modelExact共享概览：用于明细钻取的精确行身份；请核对返回的 applied_filters。任务路由要求提供 userExact。只有在使用 profile=tools 时，Codex insights 才接受 userExact，并且始终拒绝 modelExact。
intervalHours包装路由要求提供有限的 (0,744] 范围内的值。共享概览支持有界的亚小时分辨率；请查看实际的 bucket_hours 和 effective_range。
group根据 Claude 推断出的会话通道；不是发出数据的客户端，也不是 SSO 授权组。
project仅适用于特定端点，不是通用筛选条件。应用前请查阅完整 API 参考。

成本/趋势视图仅在 24 小时以内提供 10 分钟和 30 分钟选项。较早的时间范围使用每小时汇总；任意更细的请求可能会回退到受支持的原生时间桶。

浏览器选择器接受精确到秒的本地日期和时间。它会为共享链接序列化 ISO 格式的 from/to 边界以及仅供 UI 使用的 rangeMode=time 标记。该标记不是 API 筛选条件。生效边界仍遵循各端点的量化方式、数据摄取宽限期和汇总规则。

共享客户端与成本端点

端点用途
GET /api/clients/overview总量、客户端/模型/用户细分、时间序列和覆盖情况。可选的 modelTime=1 会返回模型时间序列。
GET /api/clients/overview?view=cost返回相同的成本、令牌覆盖情况、统计总体和边界；跳过未使用的项目/工具/运维诊断。未返回的字段不代表数值为零。
GET /api/clients/token-economics有效时间窗口及其前一时间窗口的成本公式、驱动因素分解、单位趋势、模型经济性、结果成本和示例用户。在运维人员完成迁移 010 的回填后设置 SESSION_TURNS_READ_FROM 之前，值将不可用。
GET /api/codex/insightsCodex 完成效率，以及日志、指标和 trace 诊断信息。
GET /api/codex/insights?profile=effort为成本/effort 视图提供仅基于日志的详细信息。指标和 trace 覆盖状态为 not_requested。
GET /api/cost/summary, /by-model, /by-user-model现有的 Claude 专用成本路由。请勿将其视为合并客户端总量。

模型的用户成本占比以已知用户成本除以所选模型的已知成本小计。未知价格会明确披露；分母未知或为零时，不会提供百分比。

Codex 已记录完成的效率

completion_usage 描述去重后、包含用量数据的完成日志，其 basis="recorded_completions"。这并不表示所选时间范围内的每次 HTTP 尝试或每个会话都具有完整遥测数据。

字段分母与范围
cache_hit_rate, cache_write_share在已记录的完成中，经验证的缓存读取/缓存写入子集占规范输入令牌的比例。
reasoning_share该群组中，经验证的推理子集占规范输出令牌的比例。
tokens_per_completion规范令牌数除以已记录的完成次数；已观测到的令牌小计不能替代缺失的规范组成部分。
cost_per_completion已知的完成成本除以全部已记录的完成次数，并保留部分价格信息的披露。
cost_per_identified_session只有包含 conversation ID 的完成记录才会计入成本分子和不同会话的分母。
unidentified_completions单独计数，不纳入已识别会话的成本单位。
completeness报告缺失的用量/会话证据、受限的汇总类别、不完整的令牌数据，以及可用的全时间范围请求/会话计数。

组成部分缺失、子集值不可能、分母为零、所有价格均未知或用量有限时，结果仍可能为 null。现有的全时间范围 HTTP 请求/会话比率仍采用更严格的保护条件。界面会在可展开的区域中展示这些比率。

Collector 和设备 API

端点接口约定
GET /api/collector功能状态、配置的公开数据摄取端点、版本、平台、令牌有效期和 installScriptUrl。
GET /api/collector/devices按所有者筛选的设备，每页最多 50 个；按原样使用返回的游标。
POST /api/collector/devices使用 name 和 platform（darwin 或 linux）注册。令牌仅返回一次。
DELETE /api/collector/devices/:id撤销属于当前所有者的设备。
GET /api/collector/package/:platform经过身份验证的下载，不嵌入凭据。
GET /api/ingest/install.sh配置了设备数据摄取时提供的公开安装程序脚本。会在终端提示输入归属信息和令牌；脚本本身不携带凭据。
GET /api/ingest/package/:platform通过设备持有者令牌认证的 darwin 或 linux 压缩包；每台设备每小时最多下载十次。不需要浏览器会话，也不嵌入令牌。
POST /api/ingest/v1/{logs,metrics,traces}仅接受设备持有者令牌。OTLP JSON/protobuf，最大 2 MiB，不支持内容压缩。

管理操作和手动下载 /api/collector/package/:platform 需要 OIDC collector:manage 权限（分析师/管理员）。查看者/演示访问权限不能管理设备。安装程序脚本和设备令牌软件包路由使用独立的数据摄取路径。设备端点不使用使用范围筛选；其响应和下载均设为 no-store。

健康状态与错误

/healthz 用于存活检查；/readyz 用于就绪检查。受保护的 /api/health/data 会报告数据摄取的新鲜度。进程正常运行并不能证明遥测数据是最新的。

格式错误的筛选条件会在查询前失败。刷新服务失败时可能返回 503 和 Retry-After: 5；凭证已过期或无效时需要登录。有界查询准入控制可在过载时拒绝请求，避免数据库工作量无限增长。

用户任务和追踪 API

用户详情默认加载概览的有效时间段。拖动图表会更新页面和任务列表；单击数据点可选择一个区间。概览请求待处理或失败时，不会将旧任务列表显示为当前列表。

使用经过会话身份验证的遥测访问。userExact 用于在所请求的时间范围内选择任务的遥测所有者；它不会限制仪表板读者只能访问自己的遥测数据。

端点请求和响应
GET /api/users/tasks必须提供 userExact，以及所选时间范围的 from/to。可选参数：client、backend、仅限 Claude 的 group，以及 sort=tokens|cost|subagents|duration。返回最多 20 个任务、unattached_codex、每个客户端的 coverage 和 partial=true。仅限 Claude 的 workflowRunId 或 workflowName 可将列表缩小到一次工作流运行。
GET /api/users/tasks/detail必须提供列表行中的 id、userExact 和相同的时间范围边界。返回 task、lanes、spans、truncated、span_total 和 why。任务不存在或所有者/时间范围不匹配时，都会返回 404。Claude 任务还会返回 environment：会话的 MCP 服务器和已加载插件。
  • 两个路由都不接受 team。请按原样传递返回的任务 ID；已禁用的客户端或格式错误的 ID 会被拒绝。
  • Claude 成本排序会从观测到的 Token 数最多的 100 个任务中选取候选项。请查看 sort_candidates.limited；候选池之外成本更高的任务可能不会出现。Codex 轮次会先计算成本，再进行排序。
  • 详情最多返回最新的 5,000 个 Span。若 Claude 详情被截断，则不会显示整个任务及各轨道的总额、模型和 why。Codex 根据完成记录计算的任务总额不受 Span 截断影响；若发生截断，叠加层仍会隐藏 KPI 行和成本带。
  • Span 属性使用允许列表。缺失的 Token 组成部分、成本、时间信息或子 Agent 证据仍为不可用。由于追踪为可选功能，任务响应始终是不完整的。

Codex 诊断追踪预览

默认的 GET /api/codex/insights 配置包含 traces、span 延迟汇总和 coverage.traces。它会返回最新的 50 条 trace，每条最多包含最新的 200 个 span。这些上限不同于 Task Trace 详情的 5,000 个 span 上限。

统计数据描述当前显示的 span。模型筛选条件仅适用于带有模型属性的 span。发生截断或 span 身份冲突时，可能会隐藏 trace 级别的时长/错误统计和详情。不会将任何指标或 trace 中观测到的令牌计入完成日志用量或成本。

effort、tools 和 performance 配置不会查询追踪：覆盖状态为 not_requested 并不能证明未进行采集。只有 profile=tools 会接受 userExact；所有 Codex insights 配置都会拒绝 modelExact。
