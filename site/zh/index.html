从用户到 Task Trace

  1. 选择时间范围和客户端筛选条件。日期选择器的“日期和时间”选项卡可输入精确的浏览器本地时间。打开 用户，然后选择用户以打开 用户详情 。
  2. 任务列表会立即显示概览有效范围内最多 20 个任务。拖动用户的使用量/成本趋势图，可同时缩小页面和任务列表的范围。点击数据点可选择一个数据桶；使用重置控件可恢复完整时段。可按令牌数、成本、子代理数或时长排序。选择工作流标记可仅显示该次运行的任务。
  3. 选择任务以打开 任务详情 。查看其令牌数、成本依据、LLM 调用、子代理和观测时长。
  4. 点击时间线栏可检查相应调用或工具。在 按模型调用 中选择一行可突出显示匹配的 LLM 时间线栏；再次选择即可清除。按 Escape 或点击 关闭 即可关闭。
查看阅读指南
代理通道主会话显示在最前，后面是观测到的子代理。颜色较深的 LLM 栏表示输入上下文更大；灰色标记表示工具，红色标记表示权限等待，虚线表示观测到的代理启动关系。
累计成本通道颜色按已知调用成本堆叠。将鼠标悬停可检查特定时间点。没有匹配跨度的 Codex 完成记录可能计入任务总额，但不会显示在色带中。
所选跨度检查可用的模型、令牌构成、成本依据、时间信息以及工具或权限元数据。不显示原始提示词、命令和路径。
费用为何这么高当所需输入可用时，基于数据的规则会说明缓存读取占比、上下文增长、通道成本占比、高成本调用、重试或权限等待。面板随后列出各模型的调用次数、已知成本及其成本占比。
模型调用按通道、调用次数和已知成本比较模型及调用来源。突出显示某行只会改变时间线的强调方式，不会改变总额。
会话环境显示 MCP 服务器的最新状态、已加载插件及其技能、代理和命令数量，以及首次调用的输入上下文。OpenTelemetry 不会报告工具定义的数量或大小。

Claude 任务代表交互跨度；Codex 任务代表已跟踪轮次，并使用关联的完成日志计算令牌数和估算成本。Codex 目前只有一个主通道；不会收集子代理数量。跟踪数据为可选，因此该任务列表仅覆盖部分仪表板活动。跟踪数据保留 90 天；无法从更早的趋势数据桶打开任务列表。

查看 Codex 诊断追踪

选择 Codex 后，打开 Analytics，并在 Codex 详情中选择 Trace 标签页。展开某条 Trace 可查看 span、父 ID、模型、工具、时长和状态，也可将 span 表格导出为 CSV。

此预览最多显示最新的 50 条追踪，每条追踪最多显示最新的 200 个 span。统计数据仅描述当前显示的 span。模型筛选器只包含带有模型属性的 span。对于过长或存在冲突的追踪，可能不显示时长和错误总数。

诊断 span 不会增加仪表板中的使用量或成本。上方的 Task Trace 会将 Codex 完成日志关联到轮次；Analytics 的 Trace 标签页是独立的诊断预览。Chat 中的推理和 SQL 步骤则是另一种独立视图。

选择时间范围和分辨率

打开时间范围选择器并选择 日期和时间 ，按浏览器时区输入精确到秒的开始和结束时间。结束时间为排他边界。共享链接会保留所选模式和 UTC 时间边界；日历日模式仍使用 UTC 日期。

超过 24 小时每小时、每天或每周。两天视图不提供 10 分钟分辨率。

查看返回的时间间隔和有效时间边界。精确输入不会改变采集宽限时间、服务器量化方式或历史汇总精度。在单位经济性图表中，虚线段会连接跨越不可用数据桶的观测端点；它们只是视觉指引，并非测量值。

区分不同维度

客户端标识发出数据的应用。后端描述观测到或推断出的提供商路径。模型标识所用模型。仅凭模型名称无法确定使用的是哪种编程客户端。

Claude 的 bedrock/enterprise 比较是根据会话渠道推断的视图。它与仪表板登录相互独立，也不是 Codex 企业版 A/B 比较。同一用户可能出现在多个渠道中。

启用后，Analytics 可通过受控的只读查询路径回答其他问题。其可用性取决于角色、模型访问权限和部署配置。
