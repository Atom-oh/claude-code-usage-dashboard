读取：已登录用户 → 仪表板结果

组织登录会提供已配置的角色。API 会先应用时间、客户端和受支持的筛选条件，然后再返回使用情况和诊断视图。请查看成本依据和覆盖范围：屏幕中可能显示已知的小计，也可能显示不可用的信号。

首次访问

  1. 打开组织的仪表板并登录。向组织者询问网址和访问权限。您正在阅读的公共网站是文档。请参阅账户和权限。
  2. 选择客户端和时间段。从所有已启用的客户端开始，并选择一个包含近期工作的时间段。检查显示的时区以及数据是否已到达。
  3. 查看 Overview。比较已知费用、已观测到的令牌数、会话数和用户数。得出结论前，请先查看数据不完整或不可用的标签。
  4. 选择与您的问题相符的菜单。使用下方的菜单图，然后按照其中的分步指南操作。常见视图可用于比较客户端；Claude 详细信息中还提供其他 Claude 专属视图。
  5. 深入查看并分享相关视图。在支持的情况下，检查模型、用户或任务。导出或分享时，请留意所选时间段和筛选条件。

解读数字前，先了解其含义

  • 已知费用不等于账单。Claude 报告的支出和受支持的标价估算都会保留各自的费用估算依据。缺少价格信息可能导致小计不完整。
  • 不可用不等于零。已观测到的令牌小计、完整的令牌组成数据和诊断覆盖范围回答的是不同问题。总数大于零并不能证明数据已完整采集。
  • 活动只是观测结果。会话数、工具使用情况和费用比率不能证明员工绩效、节省的时间或因果关系上的生产力提升。

设置时间段并使用图表

使用 UTC 日历日期，或使用日期选择器中的 날짜·시간（日期和时间）选项卡，设置精确的浏览器本地开始和结束时间。结束时间不包含在时间段内。请查看显示的实际生效时间范围：服务器汇总数据和数据接收宽限期仍会产生影响。

拖动受支持的时间序列图表可缩小页面的时间范围；使用重置控件可恢复原范围。在用户详情中，任务列表会遵循该时间范围；单击某个数据点会选中一个时间分桶。分类图表不支持选择时间范围。

所有筛选、刷新、图表、表格、导出和分享控件

跟进用户，查看其工作

打开 Users，选择一位用户，然后查看所选时间段内的任务列表。打开某项任务即可查看 Task Trace：主执行轨迹和子代理轨迹、调用、已知费用、令牌上下文、模型，以及可用的会话环境信息。

任务跟踪是可选的。Claude 交互和 Codex 跟踪的轮次具有不同的证据；缺少的调用、属性或价格仍然不可用。任务列表和详情均有明确的限制。

区分任务使用情况和诊断跟踪

Analytics 中的 Codex 诊断 Trace 选项卡是一个独立的预览功能，与 Task Trace 不同。它显示跟踪片段及其可用元数据；诊断指标和跟踪片段不会增加完成日志汇总中的使用量或费用。

区分不同维度

客户端用于标识 Claude Code 或 Codex；后端描述提供商路径；模型用于标识模型。仅凭模型名称无法确定发出请求的客户端。

Claude 的 bedrock / enterprise 对比使用推断出的会话渠道。这些渠道与仪表板登录相互独立，也不提供 Codex 企业版 A/B 对比。
