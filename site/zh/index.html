从用户到任务追踪

  1. 选择时间范围和客户端筛选条件。日期选择器中的“日期和时间”选项卡接受浏览器本地时间。打开用户，然后选择一位用户以打开用户详情。
  2. 任务列表会立即显示概览有效范围内最多 20 个任务。拖动用户的使用量/成本趋势图，可同时缩小页面和任务列表的范围。单击某个数据点可选择一个区间；重置控件可恢复整个时间段。可按 Token 数、成本、子 Agent 数或时长排序。选择工作流标记，只显示该次运行的任务。
  3. 选择一个任务以打开任务详情（任务追踪）。查看其 Token 数、成本依据、LLM 调用、子 Agent 和观测时长。
  4. 单击时间线条形图可查看对应调用或工具。选择按模型调用中的一行可高亮相应的 LLM 条形图；再次选择该行可取消高亮。按 Escape 或关闭可关闭视图。
视图阅读方法
Agent 轨道首先显示主会话，其后是观测到的子 Agent。颜色较深的 LLM 条形图表示输入上下文较大；灰色标记表示工具，红色标记表示权限等待，虚线用于连接观测到的 Agent 启动事件。
累计成本不同轨道的颜色会累积显示已知调用成本。将鼠标悬停可查看某个时间点。没有匹配 Span 的 Codex 完成记录也可能计入任务总额，但不会显示在成本带中。
选中的 Span查看可用的模型、Token 组成部分、成本依据、时间信息以及工具或权限元数据。不会显示原始提示、命令和路径。
为什么成本这么高当相关输入数据可用时，有数据支持的规则会说明缓存读取占比、上下文增长、轨道成本占比、高成本调用、重试或权限等待情况。随后，面板会列出各模型的调用次数、已知成本和成本占比。
模型调用按轨道、调用次数和已知成本比较模型及调用来源。高亮某一行只会改变时间线强调效果，不会改变总额。
会话环境显示 MCP 服务器及其最新状态、已加载插件及其技能/Agent/命令数量，以及首次调用的输入上下文。OpenTelemetry 不会报告工具定义的数量或大小。

Claude 任务表示交互 Span；Codex 任务表示经过追踪的轮次，并使用关联的完成日志获取 Token 数和估算成本。目前 Codex 只有一个主轨道；不会收集子 Agent 数量。追踪收集为可选功能，因此此任务列表仅包含部分仪表板活动。追踪数据保留 90 天；较早的趋势区间无法打开任务列表。

查看 Codex 诊断追踪

选择 Codex 后，打开 Analytics，并在 Codex 详情中选择 Trace 标签页。展开某条 Trace 可查看 span、父 ID、模型、工具、时长和状态，也可将 span 表格导出为 CSV。

此预览最多显示最新的 50 条追踪，每条追踪最多显示最新的 200 个 span。统计数据仅描述当前显示的 span。模型筛选器只包含带有模型属性的 span。对于过长或存在冲突的追踪，可能不显示时长和错误总数。

诊断 span 不会增加仪表板中的使用量或成本。上方的 Task Trace 会将 Codex 完成日志关联到轮次；Analytics 的 Trace 标签页是独立的诊断预览。Chat 中的推理和 SQL 步骤则是另一种独立视图。

选择时间范围和分辨率

打开时间段选择器并选择日期和时间，即可在浏览器时区中输入精确到秒的开始和结束时间。结束时间不包含在范围内。共享链接会保留所选模式和 UTC 时间边界；日历日模式仍使用 UTC 日期。

所选时间范围成本和趋势控件
不超过 24 小时10 分钟、30 分钟、每小时、每天或每周。一日视图从每小时分辨率开始。
超过 24 小时每小时、每天或每周。两日视图不提供 10 分钟分辨率。

请查看返回的间隔和生效时间范围。精确输入不会改变数据摄取宽限期、服务器量化方式或历史汇总精度。在单位经济分析图表中，虚线段会跨过不可用区间连接观测到的端点；它们只是视觉参考线，并非测量值。

区分不同维度

客户端标识发出数据的应用。后端描述观测到或推断出的提供商路径。模型标识所用模型。仅凭模型名称无法确定使用的是哪种编程客户端。

Claude 的 bedrock/enterprise 比较是根据会话渠道推断的视图。它与仪表板登录相互独立，也不是 Codex 企业版 A/B 比较。同一用户可能出现在多个渠道中。

启用后，Analytics 可通过受控的只读查询路径回答其他问题。其可用性取决于角色、模型访问权限和部署配置。
