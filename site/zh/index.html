从用户查看 Task Trace

  1. 选择时间范围和客户端筛选条件。打开 Users 或 Cost，然后选择用户以打开 사용자 상세（用户详情）。
  2. 点击该用户趋势图中的一个时间桶。任务列表会显示在该时间桶内开始的最多 20 个任务。可按令牌数、成本、子智能体或时长排序。
  3. 选择一个任务以打开 작업 상세（Task Trace）。查看其令牌数、成本依据、LLM 调用、子智能体和观测时长。
  4. 点击时间轴上的条形以查看对应调用或工具。选择 모델별 호출（模型调用）中的一行，可突出显示匹配的 LLM 条；再次选择可清除突出显示。按 Escape 或选择 닫기（关闭）关闭。
视图阅读方式
智能体泳道首先显示主会话，随后显示观测到的子智能体。较深的 LLM 条表示输入上下文更大；灰色标记表示工具，红色标记表示权限等待，虚线连接观测到的智能体启动事件。
累计成本泳道颜色按已知调用成本堆叠。悬停可查看某个时间点。没有匹配 span 的 Codex 完成记录可能计入任务总额，但不会显示在成本带中。
所选 span查看可用的模型、令牌组成、成本依据、时间信息以及工具或权限元数据。不会显示原始提示词、命令和路径。
왜 많이 썼나 (为什么用了这么多)当所需输入数据可用时，基于数据的规则会说明缓存读取占比、上下文增长、泳道成本占比、高成本调用、重试或权限等待。
模型调用按泳道、调用次数和已知成本比较模型及调用来源。突出显示某一行只会改变时间轴的强调效果，不会改变总额。

Claude 任务代表交互 span；Codex 任务代表追踪到的轮次，并使用关联的完成日志计算令牌数和估算成本。Codex 目前只有一个主泳道；不会采集子智能体数量。追踪采集为可选项，因此此任务列表仅包含仪表板活动的一部分。追踪数据保留 90 天；较早的趋势时间桶无法打开任务列表。

查看 Codex 诊断追踪

选择 Codex 后，打开 Analytics，并在 Codex 详情中选择 Trace 标签页。展开某条 Trace 可查看 span、父 ID、模型、工具、时长和状态，也可将 span 表格导出为 CSV。

此预览最多显示最新的 50 条追踪，每条追踪最多显示最新的 200 个 span。统计数据仅描述当前显示的 span。模型筛选器只包含带有模型属性的 span。对于过长或存在冲突的追踪，可能不显示时长和错误总数。

诊断 span 不会增加仪表板中的使用量或成本。上方的 Task Trace 会将 Codex 完成日志关联到轮次；Analytics 的 Trace 标签页是独立的诊断预览。Chat 中的推理和 SQL 步骤则是另一种独立视图。

计量项含义
Claude 报告的支出Claude 报告成本路径使用 reported_cost；计算成本诊断数据应单独保留。
AWS 标价估算Codex 和非 Anthropic Claude 定价使用受支持的 AWS 标价、路由和请求层级。这不是云服务账单。
已知成本小计汇总可用价格，并将缺失价格标注为部分数据。如果成本全部未知，则不可用。
观测到的令牌数保留可用的输入/输出对，并说明数据不完整。小计大于零并不能证明规范令牌组成数据完整。
活动指标用于了解观测到的采用情况、工具和活动。这些指标不是经过验证的员工绩效或因果生产力衡量标准。

请参阅计量定义和Codex 完成记录语义。

区分不同维度

客户端标识发出数据的应用。后端描述观测到或推断出的提供商路径。模型标识所用模型。仅凭模型名称无法确定使用的是哪种编程客户端。

Claude 的 bedrock/enterprise 比较是根据会话渠道推断的视图。它与仪表板登录相互独立，也不是 Codex 企业版 A/B 比较。同一用户可能出现在多个渠道中。

启用后，Analytics 可通过受控的只读查询路径回答其他问题。其可用性取决于角色、模型访问权限和部署配置。
