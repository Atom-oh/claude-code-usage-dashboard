用户指南

了解仪表板显示的内容、如何查看数据，以及何时需要更多证据才能得出结论。

可用功能取决于安装环境、权限和收集到的数据。本指南说明各项操作，并保留以韩语为主的界面中的实际标签，便于查找。内容已对照 v1.8.0 源码核实。

从这里开始

仪表板汇总已启用的 Claude Code 和/或 Codex 客户端发送的遥测数据。您可以用它查看观测到的使用情况、估算或报告的费用、活动和诊断信号。它不显示发票，也不能证明员工生产力、代码质量或投资回报率。

  1. 打开您所在组织的仪表板，并按指示登录。在组织登录模式下，查看者可以阅读获准查看的遥测数据；分析员和管理员角色还可能可以使用聊天功能并管理自己的收集器设备。安装状态是管理员专用功能。使用功能还要求部署已启用并配置这些功能。如果无法登录或缺少某个菜单，请咨询运营人员。
  2. 如果这是新安装，运营人员需要设置数据收集和访问权限。获准的设备所有者可以按照收集器设置进行操作，启动新的客户端会话并发出请求。请留出时间等待数据到达；收到数据本身并不能证明收集完整。
  3. 如果显示客户端选择器，请在클라이언트下选择一个客户端，并在页面顶部选择时间段。打开Overview。查看费用依据、生效时间段、总计以及任何数据不完整或缺失通知。
  4. 根据您的问题选择相应页面：要按模型或用户查看明细，请使用Cost；要查看一段时间内的变化，请使用Trends；要查看用户及其任务，请使用Users。比较结果时，请使用相同的数据源和时间段。

在窄屏幕上，点击顶部的菜单按钮（메뉴 열기）。选择页面后，导航抽屉会自动关闭。点击关闭按钮、背景区域或按 Escape 键，也可以将其关闭。

控件和结果解读

数据源和筛选器

클라이언트用于选择所有已启用的客户端、Claude Code 或 Codex。启用的客户端不止一个时，此控件才会显示。九个菜单最初使用具有可比列的共享视图。选择 Claude Code，再选择Claude 상세 보기，即可打开 Claude 的详细页面；공통 보기会返回共享视图。只会显示已启用的客户端。

在共享视图中，백엔드用于选择观测到的传输/提供方路径，例如 Bedrock Runtime、Bedrock Mantle、Anthropic 或未知。它与客户端和模型分别显示。在 Claude 详细视图中，还可能提供bedrock和enterprise这两种推断的会话渠道；它们不是客户端身份、授权组，也不能用来与 Codex 作比较。未分类的会话可能会计入总计，但会从渠道比较中排除。只安装了一个渠道时，渠道控件可能会隐藏。

사용자 검색和모델 검색支持匹配部分文本。有团队值时会显示팀选择器。团队是客户端提供的属性，只适用于界面明确说明的情况；警告会列出例外，包括采用情况、用户详细图表和 Codex 诊断信息。在 Claude 详细视图中，只有确认存在项目字段时才会显示프로젝트：请输入表格中的确切值。它只适用于 Usage 中的项目、入口点、权限模式和审批来源卡片。请阅读页面通知：某些指标不会应用所有筛选条件。切换模式时，不兼容的筛选器会被清除。

时间、刷新和图表

选择某一天的预设、이번 달（本月）或기간 직접 선택（选择时间段）。在选择器中，날짜使用 UTC 日历日；날짜·시간接受浏览器本地日期和时间，精确到秒，且结束时间不包含在范围内。选择적용以应用设置。日期预设和时间分桶使用 UTC；图表标签、精确时间和导出内容则使用浏览器所在时区显示。由于数据会进行分组，而且系统会等待近期数据完成摄取，请求的时间段和实际生效的时间段可能不同。比较数据前，请先查看生效时间段通知。

使用지금 새로고침立即刷新，或选择自动刷新间隔，也可以关闭自动刷新。后台刷新期间，之前的结果可能仍会显示；如果刷新失败，界面会明确说明。新时间段正在加载或加载失败时，不要把旧数据当作新时间段的数据。共享视图中的 Cost 和 Trends 提供추이 해상도（趋势分辨率）：时间段不超过一天时，最细可按十分钟分桶；时间段更长时，可选择更粗的分辨率。

将鼠标悬停在图表上可查看数值，并使用图例识别数据系列；有些图例还可以让您单独聚焦某个系列。在支持的时间序列图表上，拖动选择一个时间范围即可更改整个页面的时间段。点击自定义时间段标签上的 ×，或选择预设，即可清除自定义时间段并重置。分类图表无法缩放。在用户详细视图中，点击数据点可以为任务列表选择一个时间分桶；拖动则会更改页面时间段。如果结果已过时，图表操作可能不可用。

表格、导出和隐私

如果列标题支持排序，点击标题即可更改顺序。有些表格带有自己的搜索或其他选择器；顶部筛选栏并非所有表格的通用搜索功能。表格显示返回的行，不提供通用的页面控制。收集器设备有单独的기기 더 보기（加载更多）控件。显示CSV按钮时，它会导出当前显示的列和已排序的行，而不会自动导出仪表板中的所有结果。结果为空或已过时时，此按钮会被禁用。有些图表也提供自己的 CSV 下载。部分共享表格在数据行数较多时，最初只显示 20 行；使用전체 …행 보기可展开表格，CSV 导出内容也会遵循当前可见行。模型费用趋势图表提供누적/기본显示模式、数据表和可选的数据系列图例；使用모두 보기可恢复所有系列。较宽的表格可能需要水平滚动。

屏蔽功能可以隐藏屏幕上及受支持导出内容中的部分身份信息，但它并不是访问控制边界。用户详细信息和任务信息仍可能包含敏感内容。只与获准的接收者分享；先检查内容和范围；绝不要在截图、链接或公开材料中放入收集器令牌或个人/客户数据。

数字的含义

—、不可用（미수집或미산정）和空结果都不等同于观测到的零值。部分标签（부분합）表示已知的小计，不代表完整总计。总计为正数也不能证明遥测数据完整。加载中、请求错误、范围被缩短和刷新结果过时等警告，都需要分别留意。将鼠标悬停在帮助图标上，并阅读卡片副标题，了解其统计对象和分母。

对于 Anthropic 模型，Claude 详细视图中的支出仍基于报告数据；按令牌价格计算的数值是可选诊断信息。共享概览可能会用单独标记的估算值填补缺失的报告数据。Claude 的非 Anthropic 模型和 Codex 使用 AWS 目录价格进行估算。混合总计会保留各自的依据，并保留价格未知的数据。这些数值都不是发票金额，也不保证构成计费上限。观测到的令牌小计可能会遗漏某些组成部分；计算比率时需要使用完整的分母。Codex 运行时指标和追踪记录是诊断数据流，不能与完成日志中的使用量或费用相加。

Productivity

共享视图：如果有数据，令牌经济效益部分会显示费用公式、变化因素、单位费用和请求效率趋势、模型经济效益、观测到的结果单位费用以及符合条件的示例用户。此部分需要安装中的会话轮次数据准备就绪；不可用不等于零。下方有八个部分：(1) 客户端摘要，(2) 观测到的模型效率和缓存/推理占比，(3) 活动，(4) 代码结果，(5) 按工具划分的权限决定，(6) 工具结果，(7) 响应和等待时间，以及 (8) 活动指数排名靠前的用户。表格会标明未收集、未汇总和未推导的值。相关结果使用相匹配的生效时间段；导出前请等待当前响应完成。

Claude 详细视图：查看活动指数排名和用户活动；用户/会话及 PR 趋势；每百万令牌的代码行数和提交数；新增/删除行数；编辑和工具权限决定；活跃时段和语言代码编辑；每次提示的工具调用数；审批等待时间、首令牌时间和交互时间构成。收集到相关数据时，还会显示其他活动密度、权限占用情况和工具结果表。

权限决定包括自动批准，但这不代表代码已被接受。Codex 默认不会提供相同的代码行数、提交数、PR 数或活动指数指标；这些指标需要外部结果数据。即使存在这些观测数据和任意活动指数，也不能证明生产力、质量、节省的时间或因果关系上的投资回报率。

Users

共享视图：先比较各客户端的观测用户数、会话数和每位用户的费用，然后查看用户表。同一已识别用户可在所选客户端之间合并；按客户端划分的构成仍保留各自的费用依据。不同客户端的唯一用户数可能重叠，因此不能相加后当作总人数。选择已识别的用户以打开详细视图；无法打开未识别用户对应的详细视图。

详细视图包含时间段摘要和时间图表、单独加载的 90 天 UTC 每日会话热图、有数据时按客户端划分的工具/权限信息，以及任务列表。热图的每日数值是观测到的分桶会话数，并非去重会话总数。详细视图会等待与父级相匹配的时间范围；选择数据点会将任务列表缩小到一个时间分桶，拖动则会更改页面时间范围。使用전체 조회 기간의 작업可将任务列表恢复为完整时间段；关闭详细视图即可返回表格。

Claude 详细视图：查看渠道摘要、符合条件的活动指数排名、按模型系列划分的用户平均费用、观测到的用户活动，以及按用户划分的工具和 Skill 表。选择用户行以查看详细信息和任务。用户观测到的活动不是个人绩效评估。

在 Claude 详细视图中，单独的사용자 검색字段用于筛选观测活动行。打开用户详细视图时会包含所有已启用的客户端；所选的推断渠道仅适用于 Claude 的相关区域。

Cost

共享视图：从总费用和单位费用卡片开始查看，然后查看按客户端划分的模型和 Effort 费用占比以及输入/缓存构成。比较费用依据、未定价记录、整体趋势和模型/用户趋势。模型表和用户表允许您选择模型或用户，打开相匹配时间段的费用趋势；模型详细视图还会显示每位用户占已知模型费用的比例。未知价格会被排除；分母未知或为零时，不会计算占比。关闭详细视图或更改选择即可返回。Codex 的효율·Effort部分会在有数据时增加已记录完成量的效率，以及按 Effort 划分的使用情况/费用。

Analytics

共享视图：如果允许使用聊天功能，请在诊断面板上方提问。下方可比较客户端信号和首令牌时间，然后查看模型/后端诊断信息、项目标签使用情况和观测到的信号覆盖情况。项目标签由客户端提供，不是计费项目。

选择 Codex 时，Codex 상세提供런타임·메트릭和Trace。前者显示会话启动设置、指标名称搜索、已收集的指标和事件覆盖情况。Trace 显示跨度耗时和数量有限的近期追踪记录；有数据时，展开追踪记录即可查看其中的跨度。这种诊断预览不同于用户的Task Trace。它最多显示最近 50 条追踪记录，每条最多显示 200 个跨度；被截断的追踪记录仍会显示最近的跨度，但不提供整个追踪记录的耗时和错误总数。跨度数据相互冲突时，该追踪记录的详细信息可能会被隐藏。指标和追踪记录不是额外的完成量使用数据。

Claude 详细视图：Analytics 是问答页面，能否使用取决于聊天功能是否可用以及用户权限。有关示例问题、图表和限制，请参阅AI 助手。

收集器设置 (수집기 설치)

此菜单需要组织登录和设备管理权限（通常为分析员或管理员），并且必须启用设备数据摄取。此功能用于管理登录用户自己的设备。查看者应向获准的运营人员寻求帮助。请遵循您所在组织批准的安装说明。

  1. 选择 Linux 或 macOS，并阅读准备说明。输入设备名称并注册设备。
  2. 显示一次性设备令牌时，请复制并妥善保密。复制显示的安装命令，在该设备上运行，然后在终端提示时输入所需的用户 ID 和令牌。不要将令牌直接放入命令中，也不要分享令牌。
  3. 打开新的终端，启动新的 Claude Code 或 Codex 会话并发出请求。按照页面上的收件验证步骤操作，并在내 기기（我的设备）中检查最近是否收到数据。
  4. 刷新列表；如果有加载更多选项，请加载更多设备；然后检查设备的已注册、已过期或已撤销状态、过期时间和最近收件时间。如需停止某台设备，请选择해지并确认해지 확인。要重新连接，必须使用新令牌。如果出现令牌重复使用警告，请先撤销设备，再重新注册。

如果当前安装程序已配置自动续期，活跃设备会在过期前七天开始自动续期。已过期或已撤销的设备需要新令牌和重新安装。退出登录不会停止设备数据收集。最近收到数据不代表已收集所有使用数据。运营人员可参阅安装和运营部分了解更多信息。

安装状态 (설치 상태)

拥有安装状态权限的管理员可以使用상태 새로고침检查组织登录和数据库连接、只读账户状态、已启用客户端的最近收件情况、架构检查以及启动数据收集的步骤。系统会分别报告最近收件、数据过时、为空、不可用和其他状态。如果刷新失败且保留了之前的结果，界面会显示相应警告。

任务和 Trace

查找任务

  1. 打开Users，选择已识别的用户，然后找到작업 목록 · 상위 20개（任务列表，前 20 项）。列表最初使用与用户详细视图相匹配的生效时间段。在受支持的用户图表中点击一个数据点可选择一个分桶，或拖动时间范围以更新页面和列表。
  2. 选择토큰 많은 순（令牌数最多）、비용 높은 순（费用最高）、서브에이전트 많은 순（子代理最多）或느린 순（耗时最长）。列表最多显示 20 项。如有提示，Claude 费用排序最多会考虑令牌数排名前 100 的候选任务，因此候选范围之外的更贵任务可能不会显示。
  3. 查看开始时间、客户端、模型、工作流程、调用、子代理、令牌构成和观测小计、费用依据及耗时。选择工作流程徽标可筛选出对应的 Claude 工作流程运行记录；清除筛选即可返回。选择一行或开始时间以打开任务。

追踪功能是可选的，因此此列表始终不完整。没有追踪证据的任务不会显示。对于开始时间距今超过 90 天的范围，界面会视为超出追踪保留期限。Codex 任务是轮次；其令牌和费用值是根据同一对话和时间范围内的完成日志关联得到的估算值。未关联或受限的记录会特别注明。

查看任务详细信息

时间线显示主通道和观测到的子代理通道；重复的代理类型会编号并使用不同底色。输入上下文越大，LLM 调用的颜色越深；灰色表示工具，红色表示权限等待，虚线表示子代理创建。选择某个调用或其他跨度，即可查看模型、计时、令牌、费用、effort、尝试次数和可用属性。缺失的值仍表示未收集；Codex 不提供尝试次数。没有开始时间的跨度无法放置在时间线上。

分层费用带显示各通道累计的观测费用；将鼠标悬停在某一点上可查看信息。未定价的空缺和未关联的 Codex 完成记录不能构成完整的费用历史。上下文图表显示观测到的每次调用输入上下文和压缩点；在图表中选择某次调用即可查看详细信息。如果上下文窗口大小已知，Codex 可以显示上下文窗口占比；Claude 在此处不会报告窗口大小。缺失的调用不会显示，而不是显示为零。

왜 많이 썼나（为什么用量这么大）会突出显示可用的观测信息，例如重复上下文、通道占比或重试；这些只是线索，不是已证实的原因。모델별 호출（按模型划分的调用）允许您选择一行，以突出显示匹配的 LLM 调用；再次选择即可清除突出显示。세션 환경会显示观测到的 Claude 会话 MCP 服务器状态和已加载插件，而不是每次调用的清单。Codex 不提供这些会话事件。工具定义数量和令牌大小不可用。

使用任务链接控件复制或选取分享链接。链接包含任务和时间范围，接收者仍需要有仪表板访问权限；请只与获准的人分享。缺失、过期或不匹配的任务可能无法打开。详细视图最多包含最新的 5,000 个跨度。发生截断时，界面会显示警告，并隐藏 KPI 行、费用带和说明摘要；Claude 的整个任务/通道总计也会隐藏。追踪记录不完整，不能证明没有发生其他调用。关闭覆盖层即可返回；从分享的任务链接关闭时，会返回 Users。

AI 助手

聊天功能已配置、用户已通过身份验证并获准使用，且已连接经确认的只读数据源时，您可以使用Ask Claude或 Analytics 上的问题框。在组织登录模式下，查看者没有聊天权限；分析员和管理员能否使用取决于部署配置。控件可见本身并不保证服务已准备就绪。

输入使用情况问题并发送，或选择示例。Analytics 按费用、采用情况/活动、用户/工具、生产力和异常检测对示例进行分组；开始对话后，示例仍会以横向条带的形式显示。大多数预设使用所选时间段的天数；近期使用情况预设会明确询问最近三小时的情况，因此如有需要，请在问题中说明准确时间范围、客户端或其他范围。不要假设聊天问题会应用所有仪表板筛选条件。可以在对话中继续提问，并对照底层仪表板和数据覆盖通知检查回答。SQL 回答不会自动重现 Codex 完成记录去重和定价逻辑，也不会自动重现仪表板卡片使用的 Claude 非 Anthropic 费用调整。比较总计前，请核实统计对象和费用依据。

浮动窗口可以调整大小、展开、还原和关闭；关闭窗口会停止正在生成的回答，并在小组件仍处于挂载状态时保留对话。回答最多可包含三张受支持的折线图或柱状图。将鼠标悬停在图表上可查看数值，打开데이터 보기可查看图表的数据表。请阅读数据来源、费用依据、生效时间段、部分数据和行数限制标签：SQL 结果图表的数据覆盖情况可能尚未确认。助手可能不提供图表；它不提供通用的图表数据选择器或图表下载控件。仪表板表格提供 CSV 按钮时，请使用该按钮。避免在问题中提交机密或敏感个人数据。

常见工作流程

问题步骤
为什么支出增加了？选择客户端和时间段；打开 Trends 查看与上一时间段的比较，并拖动选择费用增加的范围。在 Cost 中比较模型、Effort 和用户明细，以及各自的费用依据和部分数据标签。选择模型或用户，查看对应时间段的详细信息。归因之前，请检查 Reliability 和数据收集变更。
是否有数据缺失？检查客户端、时间段、筛选器、数据新鲜度和错误通知。在 Overview 和 Analytics 中比较观测到的令牌数及费用覆盖情况。如果您有权限，请检查设备收件情况和 Installation status；否则请咨询运营人员。启动新的客户端会话并刷新。收到数据或总计为正数，都不能证明数据完整。
哪些工作费用较高？在 Cost 中查看模型和用户明细。打开 Users，选择已识别的用户，然后按费用对任务列表排序。打开某一行，查看通道、调用、费用带和上下文。请考虑追踪数据可能不完整、前 20 项和 Claude 候选任务数量限制，以及费用依据。
比较客户端和模型选择所有已启用的客户端，选择相同范围，并使用 Overview、Usage 和 Cost。查看每个客户端的后端、模型、观测到的令牌覆盖情况和费用依据。不要根据模型名称推断客户端，也不要把推断的 Claude 渠道当作客户端。选择 Cost 中的模型即可查看使用该模型的用户。

故障排查

  • 没有行：检查数据源、时间和筛选器；尝试启动新的客户端会话。某个时间段为空，可能表示没有匹配的观测数据，并不代表整个组织的使用量为零。
  • 不可用或部分数据：检查卡片上的数据覆盖情况和费用依据。某些信号、价格、项目字段、会话轮次数据或追踪记录需要额外的数据收集或设置。不要用零填补缺失数据，也不要根据小计推断数据完整。
  • 数据过旧或刷新失败：查看刷新和数据新鲜度警告，重试并检查登录状态。如果刷新失败，界面会明确说明保留的是之前的数据。请运营人员检查数据收集和权限。
  • 任务或链接缺失：检查用户、生效时间段、追踪保留期限、已启用客户端、可选追踪功能和截断通知。工作流程筛选和前 N 项限制可能会隐藏其他任务。分享链接要求接收者有访问权限，且链接必须完整。
  • 缺少控件：客户端启用状态、架构、角色、功能配置和已收集的事件都会影响界面显示内容。特别是，设备设置和状态需要相应权限；聊天功能还需要单独配置的服务和只读连接。

如需专业说明，请参阅安装、运营、架构和API 合约。
