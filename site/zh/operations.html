Trace 收集检查 · Task Trace 操作指南

连接组织 SSO

将 AUTH_MODE=oidc 设为使用 discovery/JWKS、签名 ID token、授权码和 PKCE S256 的机密 OIDC 客户端。注册精确的回调地址 https://dashboard.example.com/auth/callback。

一个共享的 Cognito 用户池可通过独立的应用客户端、回调地址、密钥和角色映射服务多个项目。应用专属的群组分配应在身份管理系统中完成。客户邮箱、域名和用户池 ID 属于配置内容，不是通用的应用规则。

配置项用途
APP_PUBLIC_URL精确的 HTTPS 源，不含路径、查询参数或片段。
OIDC_ISSUER, OIDC_CLIENT_ID精确的颁发者标识符和专用应用客户端。
OIDC_CLIENT_SECRET, SESSION_SECRET通过受保护的密钥引用进行配置。各副本必须共享会话密钥和身份配置。
OIDC_GROUPS_CLAIM顶层签名群组声明：Cognito 使用 cognito:groups；其他情况使用提供方配置的声明。
OIDC_SCOPES默认值为 openid profile。只添加配置的提供方所需的范围，包括签发刷新令牌所需的范围。
OIDC_ROLE_GROUPS将 viewer、analyst 和 admin 映射到明确群组数组的 JSON 配置。
{
  "viewer": ["YOUR_VIEWER_GROUP"],
  "analyst": ["YOUR_EDITOR_GROUP"],
  "admin": ["YOUR_ADMIN_GROUP"]
}

界面中的 editor 角色映射到 analyst；editor 不是配置角色键。未映射的群组无法登录。匹配到多个角色时，以最高角色为准。

角色权限
viewer读取整个部署的遥测数据；不能管理 Collector 或使用聊天功能。
analyst / editor读取遥测数据、使用已启用的聊天功能、下载安装程序并管理所属设备。
admin拥有 analyst 权限，并可查看部署诊断信息。

Okta 和 Keycloak 可通过适当的范围和签名群组声明提供此 OIDC 契约。请核实实际客户使用的提供方；通用支持并不代表已完成提供方验收测试。登录不会为每位用户隔离数据。

提供方设置与 SSO 运维

让登录状态最多保持 30 天

持久登录为可选功能，默认禁用。可配置一小时的授权时限和固定的 30 天登录期限：

SESSION_MAX_AGE_SECONDS=3600
SESSION_REFRESH_MAX_AGE_SECONDS=2592000

常规短会话的默认时长为 900 秒；允许值为 300–3600。刷新令牌有效期可以是 0（禁用），或 3600–2592000 秒。短会话还受提供方令牌到期时间限制，因此一小时是上限，并非保证的续期间隔。

续期由请求触发，发生在短会话即将到期或到期之后，而不是后台每小时定时执行。30 天期限从首次登录开始计算，不会滚动延长。提供方可以提前终止会话。

  • 刷新模式要求可重复使用且不轮换的刷新令牌、包含当前群组信息的新签名 ID token，以及使用 client_secret_basic 进行交换和撤销。
  • 此模式不支持仅提供轮换令牌的提供方。刷新响应中的令牌一旦轮换，就必须重新登录。
  • 使用加密的 Secure/HttpOnly cookie。会话 API 不会返回原始身份令牌。
  • 登出会清除本地 cookie，并尝试撤销刷新令牌。它不会结束提供方的 SSO 会话，不会即时撤销已复制的短期 cookie，也不会撤销设备令牌。

刷新会话设计与限制

部署经过审核的应用版本

  1. 合并发布 PR，并在干净的构建上下文中部署不可变的 vX.Y.Z 标签。记录提交，并按照部署运维手册完成发布前检查。
  2. 确认 AWS 身份、目标集群、现有 Terraform 输入、迁移状态以及可用的回滚镜像。
  3. 针对目标架构进行构建，并发布不可变的镜像标签/摘要。提供的 EKS 部署目标架构为 arm64。
  4. 按需审核完整的基础设施计划。现有部署使用兼容性验证和显式升级，不会自动重试引导初始化。
  5. 执行滚动发布，检查就绪状态和实际镜像摘要，然后验证登录、API 行为、数据接收时效性及代表性数据。

使用 /healthz 检查存活状态，使用 /readyz 检查就绪状态。源代码声明、构建成功和进程运行正常，都不能证明身份提供方可用、遥测数据及时到达或迁移已应用。

用户无法识别或被拆分检查预期的 --user-id、发出的身份信息和仪表板筛选条件。设备的 SSO 所有者不会自动成为遥测数据的归属用户。
已签发令牌但没有遥测数据重启编码客户端并产生工作负载，检查本地服务/导出器错误和设备接收情况，然后确认数据已存储。

成本详情响应较慢检查查询准入、筛选条件和有效分辨率；使用成本/工作量配置，并在更改容量前测量目标工作负载。

各平台的运维前提

所有托管选项仍需要持久化的 ClickHouse 数据库模式（schema）和正常运行的 OTel 流水线。ECS 和 EC2 需要单独编写服务、密钥和存储配置；随附的 Terraform 面向现有 EKS 环境。Lambda 需要适配应用运行时，并使用外部数据库/Collector 服务。

验证 Trace 数据路径

从一次新的交互及其预期的遥测身份、客户端和时间桶开始检查。用量总计和 Trace 可用性来自不同信号；日志成功导出不能证明 Trace 已送达。

  1. 确认当前设备软件包或组织管理员管理的设置已启用 Trace 导出，然后重启编码客户端。参阅客户端配置参考。
  2. 检查本地 Collector 服务和 Trace 导出器是否存在传输失败。继续检查经过身份验证的数据接收、中央 Trace 流水线以及存储的 otel_traces 记录。设备接收情况和进程健康状态只能确认各自所在的阶段。
  3. 在用户详情中，选择包含任务开始时间的趋势时间桶。检查目标身份和筛选条件；受支持的 Trace 任务会保留 90 天。
  4. 排查 Codex 问题时，使用完整的 insights 配置查看 Analytics 的 Trace 选项卡。成本/工作量、工具和性能配置会跳过 Trace 查询。
症状检查内容
用户有用量记录，但没有任务检查 Trace 配置、重启时间、导出的身份、任务开始时间桶和保留期限。不会将历史用量回填到 Trace 中。
Codex 完成记录不属于任何任务被 Trace 记录的轮次需要会话 ID 和唯一轮次 ID。不符合条件的轮次所对应的完成记录不会关联到任务；已关联但没有采样 span 的完成记录可能不会出现在成本范围中。
无法获取 Codex 子智能体数量当前任务视图仅包含主泳道，不会根据无关的 span 推断子智能体数量。
大型详情缺少总计检查 truncated 和 span_total。任务详情最多包含 5,000 个 span；独立的诊断预览上限为 50 条 Trace，每条 Trace 最多 200 个 span。
按模型筛选后 Codex Trace 消失只有带有模型属性的 span 才会匹配该筛选条件。清除筛选条件即可查看其他诊断 span。
