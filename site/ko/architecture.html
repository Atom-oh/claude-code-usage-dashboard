Claude Code + Codex · 문서

수집 및 쿼리 파이프라인

전용 설치 환경은 클라이언트 텔레메트리, 제한된 수집 경로, ClickHouse 저장소, 인증된 대시보드를 하나로 구성합니다.

2026년 11월 14일 업데이트 · 소스의 동작을 설명합니다. 설치된 리비전을 확인하세요.

화면에 표시되는 숫자의 출처

데이터 수집과 대시보드 액세스에는 서로 다른 경로가 사용됩니다. 다이어그램은 선택적 기기 데이터 수집 경로와 인증된 읽기 경로를 보여 줍니다. 주최자가 준비하는 워크숍 데이터 수집에는 별도로 구성된 경로를 사용할 수 있습니다. 이 그림은 OIDC 로그인과 기기 수집을 사용하는 구성 예입니다.

데이터 수집: 클라이언트 → 저장된 관측 데이터

Claude Code와 Codex는 지원되는 신호를 로컬 Collector로 내보냅니다. 등록된 기기는 인증된 수집 게이트웨이와 중앙 Collector를 거쳐 ClickHouse로 데이터를 보냅니다. 기기 자격 증명은 브라우저 로그인과 별개입니다.

읽기: 로그인한 사용자 → 대시보드 결과

조직 로그인이 구성된 역할을 제공합니다. API는 결과를 반환하기 전에 시간, 클라이언트 및 지원되는 필터를 적용합니다. 비용 기준과 데이터 범위를 확인하세요. 화면에는 확인된 소계가 표시될 수도 있고, 사용할 수 없는 신호가 표시될 수도 있습니다.

데이터 수집 경로 및 신뢰 경계 · 로그, 메트릭, 트레이스의 차이

사용자, 작업, span 연결

사용자 상세 정보에서는 정확한 텔레메트리 ID와 시간 범위를 선택합니다. /api/users/tasks는 유효 범위 내에서 시작되는 작업을 나열합니다. 사용량 차트를 드래그하면 범위가 좁아지고, 지점을 클릭하면 한 구간이 선택됩니다. /api/users/tasks/detail은 선택한 작업의 레인, 스팬 및 근거에 기반한 비용 설명을 반환합니다.

클라이언트작업 및 타이밍사용량 및 비용
Claude Codeinteraction span이 작업과 소요 시간을 식별합니다. LLM, 도구, 권한 대기 span이 타임라인을 구성하며, 관측된 에이전트 ID가 레인을 구성합니다.LLM span 토큰, 그리고 로그에서 가져와 연결한 보고 요청 비용(사용 가능한 경우) 또는 해당 가격 계산 결과입니다. 표시되는 산정 기준은 혼합될 수 있습니다.
Codex대화 ID와 고유한 턴 ID가 있는 턴이 작업을 식별합니다. 소요 시간은 관측된 span 구간이며, 기본 레인만 사용할 수 있습니다.턴 시간 구간과 연결된 고유한 사용량 포함 완료 로그에서 토큰과 AWS 정가 추정치를 가져옵니다. 샘플링 span에는 표시를 위해 일치하는 완료 기록 값이 반영됩니다.

Codex 작업 사용량은 연결된 완료 기록을 보여주는 뷰이며, 추가적인 회계 데이터 원천이 아닙니다. 연결되지 않은 완료 기록은 별도로 보고됩니다. 일치하는 샘플링 span이 없는 호출은 누적 비용 밴드에서 누락될 수 있습니다. Analytics Trace 미리보기는 진단 span을 별도로 읽습니다.

작업 상세 쿼리는 허용 목록에 있는 메타데이터만 선택합니다. UI는 식별 정보를 마스킹하며 원시 프롬프트, 명령어, 경로를 표시하지 않습니다. 이 표시 정책은 API 접근 제어를 제공하지 않습니다. 추적 데이터의 보존 기간은 90일이며 사용량 롤업과 별개입니다.

선택적 디바이스 경로는 /api/ingest/v1/{logs,metrics,traces}를 사용합니다. 브라우저 세션 쿠키로는 수집을 승인할 수 없습니다. 중앙 Collector가 ClickHouse 쓰기 자격 증명을 보유하며, PC에는 취소 가능한 디바이스 자격 증명이 발급됩니다.

주최자가 준비한 워크숍 환경에는 별도로 구성된 수집 경로가 있습니다. 이미 준비된 Collector에 마이그레이션 없이 디바이스 패키지를 덧씌우지 마세요.

수집 신뢰 경계 및 제한

신호 의미 보존

신호해석
Claude 카운터시계열 식별 정보, 누적/델타 시간성, 기준값, 재설정을 고려합니다. 누적 내보내기 값을 사용량으로 합산하지 마세요.
Codex 완료 로그완전한 식별 정보로 중복을 제거하고 사용량이 포함된 완료 기록의 가격을 한 번만 계산합니다. 중간 스트림 레코드는 사용량 합계를 추가하지 않습니다.
Codex 메트릭 및 추적진단 용도로 사용합니다. 해당 토큰 또는 비용 관측값을 완료 로그 사용량에 더하지 마세요.
캐시 및 추론 토큰정의된 경우 입력/출력의 하위 집합으로 취급합니다. 이를 표준 합계에 다시 더하면 사용량이 중복 집계됩니다.
근거 누락 또는 제한부분 플래그와 함께 확인된 소계를 유지합니다. 영향을 받는 엄격한 비율은 제공하지 않고 그 이유를 표시합니다. 누락은 0을 뜻하지 않습니다.

데이터 경계 · Codex 관측성

클라이언트, 백엔드, 세션 채널

수집 및 API 라우팅은 신호를 내보낸 클라이언트를 식별합니다. 공급자 출처와 모델 근거는 백엔드 분류에 활용됩니다. 모델 식별자만으로는 클라이언트를 식별할 수 없습니다.

Claude 세션 채널 분류기는 bedrock, enterprise, unknown을 구분합니다. 관측된 Bedrock 모델 근거와 조직/모델 대체 규칙은 세션 범위에 적용됩니다. 이 분류는 대시보드 사용자의 SSO 역할이 아닙니다.

리전/지역 Bedrock 모델 식별자와 단독 공급자 ID는 가격/백엔드 로직에서 정규화됩니다. 지원되지 않는 범위와 알 수 없는 가격은 그대로 유지하고, 모든 모델 ID에 가격이 있다고 가정하지 마세요. Codex에는 엔터프라이즈 A/B 행이 없습니다.

백엔드 가격 결정

합계를 바꾸지 않고 쿼리 작업 줄이기

  • view=cost는 공유 개요의 제한된 비용 프로필을 선택하고 사용하지 않는 진단 항목을 제외합니다.
  • profile=effort는 Codex 로그 전용 상세 정보를 선택하고 관련 없는 메트릭/추적 쿼리를 건너뜁니다.
  • Codex 로그 집계는 전체 식별 정보가 있는 이벤트를 전송하기 전에 ClickHouse에서 압축합니다. 집계 계열 제한은 계속 표시됩니다.
  • 단일 실행 캐싱과 제한된 요청 수용은 필터 식별 정보, 기한, 과부하 오류를 유지하면서 반복 작업을 공유합니다.

이러한 메커니즘은 작업량을 줄여 주지만 동시 사용자 140명에 대한 용량을 보장하지는 않습니다. 대상 설치 환경에서 대표적인 필터 다양성, 캐시가 비어 있는 상태의 트래픽, 수집량, 쿼리 지연 시간을 측정하세요.

비용 쿼리 성능

대시보드 및 디바이스 접근

OIDC는 서명된 ID를 검증하고 명시적 그룹 값을 viewer, analyst, admin에 매핑합니다. 권한이 있는 뷰어는 설치 환경 전체의 텔레메트리를 읽을 수 있습니다. 이는 직원별 행 격리가 아닙니다.

디바이스 토큰은 텔레메트리 수집 및 설치 패키지 다운로드를 허용하며, 브라우저 액세스는 허용하지 않습니다. 토큰은 각각 별도로 소유되며 만료되거나 취소됩니다. 텔레메트리 귀속 정보는 클라이언트가 제공합니다. SSO 세션이나 토큰 소유권만으로 텔레메트리 이메일의 진위가 자동으로 확인되는 것은 아닙니다.

PII 마스킹은 표시 기능이며 API 접근 제어가 아닙니다. 수집 필터는 알려진 콘텐츠 필드를 제거하지만, 지원되는 다른 메타데이터에 임의로 입력된 비밀 정보까지 탐지할 수는 없습니다.

SSO 구성 및 세션 새로 고침 · Collector 설치

배포 경계

대시보드 이미지에는 웹 UI와 API가 포함됩니다. ClickHouse, 스키마, OTel Collector는 모든 플랫폼에서 별도 구성 요소입니다. 현재 Compose 파일에는 Collector가 포함되지 않으며, EKS Terraform은 기존 클러스터 종속성을 재사용합니다. ECS/EC2에는 검토된 인프라, 자격 증명, 네트워킹, 상태 확인 및 영속성 구성이 필요하고, Lambda에는 애플리케이션 런타임 조정이 필요합니다.

필수 구성 요소 · 호스팅 옵션 비교

스키마 수명 주기, 애플리케이션 이미지, Collector 정책, 런타임 옵션은 각각 독립적인 배포 상태를 가집니다. 빌드 또는 Terraform 검증에 성공해도 실제 롤아웃이나 마이그레이션이 완료되었다고 볼 수 없습니다.
