01. 사용자의 작업을 개별 호출까지 추적하기

사용자의 비용, 토큰 양 또는 도구 활동을 자세히 살펴봐야 할 때 이 절차를 사용하세요. 작업 목록은 활동 중 일부를 추적한 결과이므로 먼저 사용량 총계를 확인한 다음, 이용 가능한 작업 증거를 살펴보세요.

  1. 확인하려는 사용자와 기간 선택하기

    Users를 열고 클라이언트를 선택한 다음 작업이 포함된 기간을 설정하세요. 식별된 사용자 행을 선택하면 사용자 상세가 열립니다. 카드와 차트를 비교하기 전에 적용된 기간을 나타내는 행을 확인하세요. Claude 세부 정보에서 사용자 상세에는 활성화된 모든 클라이언트가 포함될 수 있으며, 추론된 채널 필터는 Claude 영역에만 적용됩니다.

  1. 차트 범위를 좁히고 해당 작업 확인하기

    사용자의 사용량/비용 차트에서 확인하려는 구간을 드래그하세요. 페이지 기간과 작업 목록의 범위가 함께 좁혀집니다. 한 지점을 클릭하면 대신 해당 구간 하나가 선택됩니다. 지점 선택을 해제하려면 전체 조회 기간의 작업을 사용하고, 드래그로 선택한 범위를 넓히려면 페이지 기간을 초기화하세요.

  2. 적절한 정렬 및 비용 기준로 작업 선택하기

    작업 목록 · 상위 20개에서 토큰, 비용, 하위 에이전트 또는 기간을 비교하세요. 워크플로 배지를 선택하면 해당 실행만 표시됩니다. 비용이 높은 작업을 선택하기 전에 비용 기준 배지를 확인하세요. Claude의 비용 순위는 토큰 수가 가장 많은 후보 100개로 제한될 수 있으므로 상위 20개 목록만으로 전체 비용을 빠짐없이 감사할 수는 없습니다.

  1. 결론을 내리기 전에 레인을 확인하세요

    작업을 여세요. 작업의 토큰 소계, 비용 기준, 호출 수, 기간을 확인한 다음 기본 레인과 관측된 하위 에이전트를 살펴보세요. 같은 에이전트 유형이 반복되더라도 각 에이전트는 별도의 번호가 매겨진 레인으로 표시됩니다. 막대의 너비는 관측된 기간을 나타내며, 더 어두운 LLM 막대는 입력 컨텍스트가 더 크다는 뜻입니다. 회색 막대는 도구, 빨간색 표시는 권한 대기, 점선 연결은 관측된 에이전트 시작을 나타냅니다.

설명이 필요한 호출 선택하기

LLM, 도구 또는 대기 구간을 클릭하세요. 측면 패널에는 선택한 항목에서 사용 가능한 속성(모델, 토큰 구성 요소, 타이밍, 비용 기준, 도구 또는 권한 메타데이터)이 표시됩니다. 없는 속성은 미수집으로 표시됩니다.

attempt는 Claude 스팬에 해당 정보가 있을 때만 표시됩니다. 값이 없다고 해서 시도가 한 번뿐이었거나 재시도가 0회였다는 뜻은 아닙니다. 여기서 Codex는 이 필드를 제공하지 않습니다. 화면에는 원시 프롬프트, 명령어, 경로가 표시되지 않으므로 콘텐츠 전체를 감사할 수 있는 화면은 아닙니다.

  1. 비용, 컨텍스트, 모델 연결해서 살펴보기

    누적 비용 밴드에 마우스를 올려 레인별 기여도를 비교하세요. 그런 다음 컨텍스트 차트와 왜 많이 썼나 관측 내용을 살펴보세요. 모델별 호출 행을 선택하면 해당 LLM 막대가 강조 표시됩니다. 같은 행을 다시 선택하면 강조 표시가 해제됩니다. 강조 표시는 눈에 띄는 부분만 바꾸며 작업 총계는 바꾸지 않습니다. 다음 분석 대상을 정하기 전에 큰 컨텍스트가 반복되는지, 특정 레인의 비중이 큰지, 비용이 높은 호출이나 기록된 대기가 있는지 살펴보세요.

  2. 세션 컨텍스트를 확인하고 동일한 증거 공유하기

    세션 환경에는 관측된 Claude MCP 상태와 로드된 플러그인이 표시됩니다. 이는 세션 관측 정보이지, 호출별 도구 목록은 아닙니다. 작업 링크를 복사하면 해당 작업과 시간 범위를 보존할 수 있지만, 받는 사람도 여전히 액세스 권한이 있어야 합니다. Codex 완료 총계에는 비용 밴드에 일치하는 샘플링 스팬이 없는 연결 기록이 포함될 수 있습니다.

작업이 없거나 불완전한 경우: 사용자 식별, 기간, 추적 구성, 90일 보존 기간을 확인하세요. 세부 정보는 최신 스팬 5,000개로 제한됩니다. 잘린 보기에서는 필요한 경우 전체 작업 요약이 숨겨집니다. 트레이스에 없다는 이유만으로 활동이 없었다고 볼 수는 없습니다.

02. 비용 변화 및 토큰 효율성 설명하기

서로 비교할 수 있는 기간과 비용 기준부터 확인하세요. 총계에서 모델 또는 사용자로 범위를 좁힌 다음, 토큰 경제성과 추적된 작업을 사용해 관측된 변화를 파악하세요.

  1. 비교 범위 고정하기

    클라이언트, 백엔드, 기간을 선택하세요. 표시된 적용 기간을 확인하고 Trends에서 길이가 같은 기간을 비교하세요. Cost에서는 보고된 Claude 지출, 추정된 비 Anthropic Claude 또는 Codex 지출, 혼합 또는 일부 데이터에 기반한 소계를 구분하세요. 가격 정보가 없으면 비용은 이용 불가 상태로 유지됩니다. 표시되는 비용은 어떤 경우에도 청구서가 아닙니다.

  2. 모델 또는 사용자별 기여도 찾기

    모델 및 사용자 분석을 사용해 변화를 일으킨 부분을 찾으세요. 지원되는 경우 모델을 선택해 해당 모델을 사용한 사용자를 확인하거나, 사용자를 선택해 일치하는 기간의 상세 정보를 확인하세요. 모델 사용자별 비중은 확인된 모델 비용 소계를 분모로 사용합니다. 확인된 비용에서 차지하는 비중에는 가격이 책정되지 않은 관측값이 반영되지 않습니다.

  1. 6가지 요소로 구성된 비용 계산식 읽기

    Productivity를 여세요. 세션 턴 데이터가 준비되면 비용 방정식에 활성 사용자 수, 사용자당 세션 수, 세션당 턴 수, 턴당 요청 수, 요청당 토큰 수, 토큰 가격이 연결되어 표시됩니다. 먼저 계산에 일치한 세션 수와 제외된 관측값을 확인하세요. 이 계산식은 조건을 충족한 모집단을 설명합니다.

  2. 증가분과 요청당 변화를 구분하기

    드라이버 분해에서 관측된 비용 차이에 각 요소가 기여한 방향과 크기를 확인하세요. 이전 총계와 현재 총계를 요인 합계와 비교하세요. 요청당 토큰 수나 단가가 낮아져도 사용자 또는 세션 수가 늘면 지출이 증가할 수 있습니다. 화면의 낭비 그룹은 선택한 요소를 회계상 분류한 이름이지, 사람이나 요청이 낭비였다는 증거가 아닙니다.

  1. 분모를 확인하면서 단위 비용, 토큰, 캐시 읽기

    사용자/세션/요청당 비용과 요청당 토큰 수를 살펴본 다음, 모델별 비용 구조와 사용 가능한 캐시 또는 추론 비중을 비교하세요. 각 지표의 도움말과 데이터 범위를 확인하세요. 관측된 토큰 소계는 비율 계산에 사용되는 완전한 구성 요소와 서로 대체할 수 없습니다. 단위 비용 차트에서 점선 구간은 이용할 수 없는 구간을 사이에 둔 관측 시점의 끝점을 연결한 것입니다. 해당 구간의 실제 측정 비용을 나타내지는 않습니다.

  2. 변경하기 전에 실제 작업으로 돌아가기

    관련 사용자를 열고 추적된 작업을 비용순으로 정렬하세요. 모델 변경, 반복되는 컨텍스트, 캐시 관측값, 도구 활동, 기록된 오류 또는 재시도를 비교하세요. 이런 관측 내용은 프롬프트나 워크플로 검토에 도움이 될 수 있지만, 인과적인 비용 절감, 코드 품질 또는 직원 생산성을 입증하지는 않습니다. 실제 워크플로를 변경한 뒤에는 동일한 범위에서 다시 확인하세요.

총비용은 늘지만 단위 비용은 비슷한 경우

먼저 활성 사용자, 세션, 요청 수를 살펴보세요. 관측된 활동이 늘면 단위별 결과가 나빠지지 않아도 총계가 커질 수 있습니다.

요청당 토큰 수 또는 모델 가격이 바뀐 경우

모델 구성, 사용 가능한 경우의 effort/speed 등급, 컨텍스트, 캐시 구성을 살펴보세요. 서로 일치하는 모집단을 비교한 다음 대표적인 작업을 여세요.

03. 도구, MCP, 스킬, 권한 확인하기

도구 활동은 작업이 어떤 방식으로 수행되었는지 설명하는 데 도움이 됩니다. 호출 수를 비교하기 전에 도구 호출, 권한 결정, 결과, 세션에 로드된 환경을 구분하세요.

  1. Usage에서 필요한 데이터 소스 확인하기

    공유 Usage에서 토큰 구성과 사용 가능한 클라이언트별 도구 활동을 비교하세요. 클라이언트와 기간은 동일하게 유지하세요. Claude 전용 도구, MCP, 스킬 섹션을 보려면 Claude Code와 Claude 상세 보기를 선택하세요. 클라이언트가 제공하지 않는 신호는 0이 아니라 이용 불가로 표시됩니다.

  2. 호출과 결과를 함께 확인하기

    수집된 경우 도구 이름, 횟수, 실패, 타이밍을 비교하세요. 읽기/검색, 편집, 셸 실행, 에이전트 호출과 같은 일반 작업을 구분하세요. 호출 수가 많다고 해서 자동으로 좋거나 나쁘다고 할 수는 없습니다. 작업을 살펴보고 같은 작업이 반복되는지 확인하세요. 권한 승인과 성공적인 실행은 서로 다른 관측 정보입니다.

  1. 서버 및 작업별로 MCP 확인하기

    관측된 MCP 서버와 도구 이름을 확인하세요. 세션 환경에 연결된 서버가 표시되면 연결이 관측된 것입니다. 서버가 제공하는 모든 도구가 실행되었다는 뜻은 아닙니다. 실패 상태는 확인이 필요한 신호이지, 비용 또는 작업 실패의 완전한 설명은 아닙니다. MCP 이벤트가 없으면 이 보기가 비어 있을 수 있습니다.

  2. 스킬 사용과 로드된 플러그인 구분하기

    사용 가능한 스킬 호출 및 출처 표시 표를 살펴보세요. 로드된 플러그인 수와 관련 세션 관측 정보는 별도로 확인하세요. 플러그인을 로드했다고 해서 플러그인에 포함된 모든 스킬이나 명령어가 실행된 것은 아닙니다. 스킬에 귀속된 비용은 총지출에 더해지는 추가 금액이 아닙니다.

  1. 권한 및 대기 확인하기

데이터 소스와 필터

클라이언트에서는 활성화된 전체 클라이언트, Claude Code 또는 Codex를 선택합니다. 둘 이상의 클라이언트가 활성화된 경우에 표시됩니다. 처음에는 아홉 개 메뉴가 비교 가능한 열을 사용하는 공통 보기로 열립니다. Claude Code를 선택하고 Claude 상세 보기를 선택하면 Claude 전용 상세 페이지가 열립니다. 공통 보기를 선택하면 공통 보기로 돌아갑니다. 활성화된 클라이언트만 표시됩니다.

공통 보기에서 백엔드는 Bedrock Runtime, Bedrock Mantle, Anthropic 또는 알 수 없음과 같이 관측된 전송/제공자 경로를 선택합니다. 이는 클라이언트 및 모델과 별개입니다. Claude 상세 보기에서는 추론된 세션 채널인 bedrock과 enterprise가 제공될 수 있습니다. 이 채널은 클라이언트 식별 정보, 권한 그룹 또는 Codex와의 비교 기준이 아닙니다. 분류되지 않은 세션은 합계에 포함되면서 채널 비교에서는 제외될 수 있습니다. 채널이 하나뿐인 설치 환경에서는 채널 컨트롤이 숨겨질 수 있습니다.

사용자 검색 및 모델 검색은 일부 텍스트가 일치해도 결과를 찾습니다. 팀 값이 있으면 팀 선택기가 표시됩니다. 팀은 클라이언트가 제공하는 속성이며 화면에 지정된 경우에만 적용됩니다. 화면의 알림에는 적용되지 않는 항목이 표시되며, 여기에는 도입률, 사용자 상세 차트 및 Codex 진단이 포함됩니다. Claude 상세 보기에서 프로젝트는 프로젝트 필드가 확인된 경우에만 표시됩니다. 이 필터에는 표에 있는 값을 정확히 입력하세요. Usage의 프로젝트, 진입점, 권한 모드 및 승인 출처 카드에만 적용됩니다. 일부 측정값에는 모든 필터가 적용되지 않을 수 있으므로 페이지의 알림을 읽으세요. 모드를 변경하면 호환되지 않는 필터는 초기화됩니다.

시간, 새로고침 및 차트

일일 프리셋, 이번 달 또는 기간 직접 선택을 선택합니다. 날짜 선택기에서 날짜는 UTC 기준 달력 날짜를 사용합니다. 날짜·시간은 브라우저의 현지 날짜 및 시간을 초 단위까지 입력하며, 종료 시각은 범위에 포함되지 않습니다. 적용을 선택해 적용합니다. 날짜 프리셋과 시간 구간은 UTC를 사용합니다. 차트 레이블, 정확한 시각 및 내보내기는 브라우저 시간대로 표시됩니다. 데이터는 구간별로 그룹화되고 최근 데이터가 도착할 시간을 확보하므로 요청한 기간과 실제 적용된 기간이 다를 수 있습니다. 비교하기 전에 적용된 기간 알림을 읽으세요.

지금 새로고침을 사용하면 즉시 새로고침하거나 자동 새로고침 간격을 선택할 수 있습니다. 자동 새로고침은 끌 수도 있습니다. 백그라운드에서 새로고침하는 동안 이전 결과가 계속 표시될 수 있으며, 실패한 경우에는 실패했다는 내용이 명시적으로 표시됩니다. 새 기간을 불러오는 중이거나 불러오기에 실패한 경우, 이전 데이터를 새 기간의 데이터로 간주하지 마세요. 공통 보기의 Cost 및 Trends에는 추이 해상도가 있습니다. 기간이 하루 이하이면 최대 10분 단위 구간을, 더 긴 기간이면 더 넓은 구간을 선택할 수 있습니다.

차트에 마우스를 올리면 값을 읽을 수 있습니다. 범례에서 각 계열을 확인하세요. 일부 범례에서는 계열 하나에 초점을 맞출 수도 있습니다. 지원되는 시계열 차트에서 시간 구간을 드래그하면 페이지 전체의 기간이 변경됩니다. 사용자 지정 기간 표시의 ×를 눌러 지우거나 프리셋을 선택해 초기화할 수 있습니다. 범주형 차트는 확대할 수 없습니다. 사용자 상세 보기에서는 데이터 포인트를 클릭해 작업 목록을 시간 구간 하나로 좁힐 수 있으며, 드래그하면 페이지 기간이 변경됩니다. 결과가 최신 상태가 아닐 때는 차트 작업을 사용할 수 없을 수 있습니다.

표, 내보내기 및 개인정보 보호

열 머리글에 정렬 기능이 있으면 머리글을 클릭해 순서를 변경합니다. 일부 표에는 자체 검색이나 다른 선택기가 있습니다. 상단 필터 바에서 모든 표를 일괄 검색할 수 있는 것은 아닙니다. 표에는 반환된 행이 표시되며, 표가 페이지 전체를 제어하는 일반 컨트롤을 제공하지는 않습니다. 수집기 기기에는 별도의 기기 더 보기 컨트롤이 있습니다. CSV 버튼이 표시되는 경우, 자동으로 대시보드의 모든 결과를 내보내는 것이 아니라 화면에 표시된 열과 정렬된 행을 내보냅니다. 결과가 비어 있거나 최신 상태가 아닐 때는 버튼을 사용할 수 없습니다. 일부 차트에는 별도의 CSV 다운로드 기능이 있습니다. 공통 표 중 일부는 행이 더 있더라도 처음에는 20개 행만 표시합니다. 전체 …행 보기를 사용해 펼칠 수 있으며, CSV에는 화면에 표시되는 행이 포함됩니다. 모델 비용 추이 차트에는 누적/기본 표시 모드, 데이터 표 및 선택 가능한 범례 계열이 있습니다. 모두 보기를 사용하면 모든 계열을 다시 표시할 수 있습니다. 표가 넓으면 가로로 스크롤해야 할 수 있습니다.

마스킹을 사용하면 화면과 지원되는 내보내기에서 식별 정보 일부를 숨길 수 있지만, 이는 액세스 제어를 대신하지 않습니다. 사용자 상세 정보와 작업 정보에도 민감한 내용이 있을 수 있습니다. 승인된 수신자에게만 공유하고, 공유 전에 내용과 기간을 확인하세요. 수집기 토큰이나 개인/고객 데이터를 스크린샷, 링크 또는 공개 자료에 절대 포함하지 마세요.

이 메뉴를 사용하려면 조직에 로그인하고 기기 관리 권한(일반적으로 분석가 또는 관리자)을 보유해야 하며, 기기 데이터 수집도 활성화되어 있어야 합니다. 로그인한 사용자의 기기를 관리합니다. 조회자는 권한이 있는 운영 담당자에게 도움을 요청해야 합니다. 조직에서 승인한 설치 안내를 따르세요.

  1. Linux 또는 macOS를 선택하고 준비 안내를 읽습니다. 기기 이름을 입력하고 등록합니다.
  2. 기기 토큰이 표시될 때 복사해 비밀로 보관합니다. 대시보드에서는 토큰을 한 번만 표시합니다. 표시된 설치 명령을 복사해 해당 기기에서 실행한 다음 터미널 프롬프트에 요청된 사용자 ID와 토큰을 입력합니다. 명령에 토큰을 직접 넣거나 다른 사람과 공유하지 마세요.
  3. 새 터미널을 열고 새 Claude Code 또는 Codex 세션을 시작해 요청을 보냅니다. 페이지의 수신 확인 절차를 따르고 내 기기에서 최근 데이터 수신을 확인합니다.
  4. 목록을 새로고침하고, 표시되는 경우 기기를 더 불러옵니다. 등록, 만료 또는 해지 상태, 만료 시각 및 마지막 데이터 수신을 확인합니다. 기기를 중지하려면 해지를 선택한 다음 해지 확인을 선택합니다. 다시 연결하려면 새 토큰이 필요합니다. 토큰 재사용 경고가 표시되면 토큰을 해지하고 새로 등록하세요.

현재 설치 환경에서 설정된 경우 활성 기기는 만료 7일 전부터 자동으로 갱신됩니다. 만료되었거나 해지된 기기를 사용하려면 새 토큰을 받고 다시 설치해야 합니다. 로그아웃해도 기기의 데이터 수집은 중지되지 않습니다. 최근 데이터가 수신되었다고 해서 모든 사용량이 수집되었다는 뜻은 아닙니다. 운영 담당자용 자세한 내용은 설치 및 운영을 참조하세요.

설치 상태

설치 상태 권한이 있는 관리자는 상태 새로고침을 사용해 조직 로그인 및 데이터베이스 연결, 읽기 전용 계정 상태, 활성화된 클라이언트의 최근 데이터 수신, 스키마 점검 및 데이터 수집 시작 단계를 확인할 수 있습니다. 최근 데이터 수신, 오래된 데이터, 데이터 없음, 사용 불가 및 기타 상태는 각각 구분해 표시됩니다. 새로고침에 실패한 후 이전 결과가 계속 표시되면 화면에 경고가 표시됩니다.

점검이 성공했다고 해서 텔레메트리 전체, 실제 마이그레이션, MFA 또는 백업 복구가 검증된 것은 아닙니다. 운영 담당자가 별도로 확인해야 합니다. 프로젝트 필터는 프로젝트 필드가 확인된 경우에만 사용할 수 있습니다. 운영 및 아키텍처를 참조하세요.

작업과 Trace

작업 찾기

  1. Users를 열고 식별된 사용자를 선택한 다음 작업 목록 · 상위 20개를 찾습니다. 처음에는 사용자 상세 보기와 일치하는 적용 기간이 사용됩니다. 지원되는 사용자 차트에서 데이터 포인트를 클릭하면 구간 하나를 선택할 수 있습니다. 기간을 드래그하면 페이지와 목록이 업데이트됩니다.
  2. 토큰 많은 순, 비용 높은 순, 서브에이전트 많은 순 또는 느린 순을 선택합니다. 목록에는 최대 20개 항목이 표시됩니다. Claude 비용 순위는 표시된 경우 최대 토큰 후보 상위 100개를 고려하므로, 이 후보 범위 밖에 있는 더 비싼 작업이 표시되지 않을 수 있습니다.
  3. 시작 시각, 클라이언트, 모델, 작업 흐름, 호출 수, 서브에이전트, 토큰 구성 및 관측된 소계, 비용 산정 기준과 소요 시간을 확인합니다. 작업 흐름 배지를 선택하면 해당 Claude 작업 흐름 실행으로 범위를 좁힙니다. 필터를 지우면 원래 결과로 돌아갑니다. 행 또는 시작 시각을 선택해 작업을 엽니다.

Trace 기능은 선택 사항이므로 이 목록은 항상 일부만 표시합니다. Trace 근거가 없는 작업은 표시되지 않습니다. UI에서는 90일보다 더 이전부터 시작하는 범위를 Trace 보존 기간을 벗어난 것으로 처리합니다. Codex 작업은 턴입니다. 토큰 및 비용 값은 같은 대화와 시간 구간에 속하는 완료 로그에서 연결한 추정치입니다. 연결되지 않았거나 제한된 레코드는 따로 표시됩니다.

작업 상세 정보 읽기

타임라인에는 기본 레인과 관측된 서브에이전트 레인이 표시됩니다. 같은 유형의 에이전트는 번호가 매겨지고 서로 다른 음영으로 표시됩니다. LLM 호출은 입력 컨텍스트가 클수록 더 진하게 표시됩니다. 회색은 도구, 빨간색은 권한 대기, 점선은 서브에이전트 생성을 나타냅니다. 호출이나 다른 Span을 선택하면 모델, 시간, 토큰, 비용, Effort, 시도 횟수 및 사용 가능한 속성을 확인할 수 있습니다. 값이 없으면 수집되지 않은 것으로 처리합니다. Codex는 시도 횟수를 제공하지 않습니다. 시작 시각이 없는 Span은 타임라인에 배치할 수 없습니다.

누적 비용 막대에는 레인별 관측 비용의 누계가 표시됩니다. 포인트에 마우스를 올리면 값을 확인할 수 있습니다. 가격을 알 수 없는 구간과 연결되지 않은 Codex 완료 기록은 완전한 비용 내역이 아닙니다. 컨텍스트 차트에는 호출별 관측 입력 컨텍스트와 압축 지점이 표시됩니다. 차트에서 호출을 선택하면 상세 정보를 확인할 수 있습니다. Codex는 알려진 경우 컨텍스트 창에서 차지하는 비율을 표시할 수 있습니다. 여기서는 Claude 컨텍스트 창 크기를 보고하지 않습니다. 누락된 호출은 0이 아니라 표시되지 않는 것입니다.

왜 많이 썼나에는 반복된 컨텍스트, 레인 비율 또는 재시도와 같이 확인 가능한 관측 정보가 표시됩니다. 이는 단서이지 입증된 원인은 아닙니다. 모델별 호출에서는 행을 선택해 해당 LLM 호출을 강조 표시할 수 있습니다. 다시 선택하면 강조 표시가 해제됩니다. 세션 환경에는 관측된 Claude 세션의 MCP 서버 상태와 로드된 플러그인이 표시되며, 호출별 목록은 표시되지 않습니다. Codex는 이러한 세션 이벤트를 제공하지 않습니다. 도구 정의 개수와 토큰 크기는 사용할 수 없습니다.

작업 링크 컨트롤을 사용해 공유 링크를 복사하거나 선택합니다. 링크에는 작업과 해당 시간 범위가 포함되며, 링크를 받은 사람도 대시보드에 액세스할 수 있어야 합니다. 권한이 있는 사람과만 공유하세요. 작업을 찾을 수 없거나 만료되었거나 일치하지 않으면 열리지 않을 수 있습니다. 상세 보기는 최신 Span 5,000개까지만 표시합니다. 잘린 경우 UI에 경고가 표시되고 KPI 행, 비용 막대 및 설명 요약은 표시되지 않습니다. Claude의 전체 작업/레인 합계도 표시되지 않습니다. Trace가 불완전하다고 해서 다른 호출이 없었다는 뜻은 아닙니다. 오버레이를 닫으면 이전 화면으로 돌아갑니다. 공유 작업 링크를 열어 오버레이를 닫으면 Users 페이지로 이동합니다.

AI 어시스턴트

채팅이 구성되고, 인증 및 권한이 설정되어 있으며, 읽기 전용 데이터 연결이 확인된 경우 Ask Claude 또는 Analytics의 질문 입력란을 사용하세요. 조직 로그인에서 조회자에게는 채팅 권한이 없습니다. 분석가 및 관리자의 액세스는 배포 설정에 따라 달라집니다. 컨트롤이 화면에 보인다고 해서 서비스가 반드시 준비된 것은 아닙니다.

사용량에 관한 질문을 입력해 전송하거나 예시 질문을 선택하세요. Analytics는 예시를 비용, 도입률/활동, 사용자/도구, 생산성 및 이상 탐지로 묶어 표시합니다. 대화가 시작된 후에도 예시는 가로 목록으로 계속 표시됩니다. 대부분의 프리셋은 선택한 기간의 일수를 사용합니다. 최근 사용량 프리셋은 명시적으로 최근 3시간을 요청합니다. 필요하면 질문에 정확한 시간 범위, 클라이언트 또는 다른 범위를 적으세요. 모든 대시보드 필터가 채팅 질문에 적용된다고 가정하지 마세요. 대화에서 후속 질문을 하고 대시보드의 기본 데이터와 데이터 범위 알림을 확인해 답변을 검증하세요. SQL 답변은 Codex 완료 기록의 중복 제거 및 가격 산정, 또는 대시보드 카드에서 사용하는 비 Anthropic Claude 비용 조정을 자동으로 재현하지 않습니다. 합계를 비교하기 전에 대상 데이터 집단과 비용 산정 기준을 확인하세요.

떠 있는 창은 크기 조정, 펼치기, 원래 크기로 복원 및 닫기가 가능합니다. 창을 닫으면 진행 중인 답변은 중단되지만 위젯이 화면에 있는 동안 대화는 유지됩니다. 답변에는 지원되는 선형 또는 막대형 차트가 최대 3개까지 포함될 수 있습니다. 값은 마우스를 올려 확인하고 데이터 보기를 열어 차트의 데이터 표를 살펴보세요. 데이터 소스, 비용 산정 기준, 적용 기간, 부분합 및 행 제한 레이블을 확인하세요. SQL 결과 차트의 데이터 범위는 확인되지 않았을 수 있습니다. 어시스턴트는 차트 없이 답변할 수도 있습니다. 일반적인 차트 데이터 선택기나 차트 다운로드 컨트롤은 제공하지 않습니다. 대시보드 표에 CSV 버튼이 있으면 사용하세요. 질문에 비밀 정보나 민감한 개인 정보를 입력하지 마세요.

데이터가 누락되었나요?클라이언트, 기간, 필터, 최신 상태 및 오류 알림을 확인합니다. Overview와 Analytics에서 관측된 토큰 및 비용의 데이터 범위를 비교하세요. 권한이 있다면 기기 데이터 수신 및 설치 상태를 확인하고, 그렇지 않으면 운영 담당자에게 문의합니다. 새 클라이언트 세션을 실행하고 새로고침하세요. 데이터가 수신되었거나 합계가 양수라고 해서 완전한 것은 아닙니다.
비용이 많이 든 작업은 무엇인가요?Cost에서 모델 및 사용자별 내역을 살펴봅니다. Users를 열고 식별된 사용자를 선택한 다음 작업 목록을 비용순으로 정렬합니다. 행을 열어 레인, 호출, 비용 막대 및 컨텍스트를 확인합니다. Trace 수집이 일부에 그칠 수 있고, 상위 20개 및 Claude 후보 제한이 있으며, 비용 산정 기준을 확인해야 합니다.
클라이언트 및 모델을 비교하려면 어떻게 하나요?활성화된 클라이언트를 모두 선택하고 동일한 기간을 지정한 다음 Overview, Usage 및 Cost를 사용합니다. 클라이언트별 백엔드, 모델, 관측된 토큰 데이터 범위 및 비용 산정 기준을 확인하세요. 모델 이름만으로 클라이언트를 추론하거나 추론된 Claude 채널을 클라이언트로 간주하지 마세요. Cost에서 모델을 선택하면 해당 모델의 사용자를 확인할 수 있습니다.
기기를 등록하거나 해지하려면 어떻게 하나요?필요한 권한과 설정된 데이터 수집이 있다면 수집기 설정에서 기기 이름을 지정해 등록하고, 토큰이 표시될 때 안전하게 복사한 다음 새 세션을 설치하고 확인합니다. 데이터 수집을 중지하려면 기기를 선택하고 해지를 확인합니다. 수집기 설정을 참조하세요.

문제 해결

  • 행이 표시되지 않음: 데이터 소스, 시간 및 필터를 확인하고 새 클라이언트 세션을 실행해 보세요. 기간에 결과가 없다는 것은 조직 전체의 사용량이 0이라는 뜻이 아니라, 조건에 맞는 관측 데이터가 없다는 뜻일 수 있습니다.
  • 사용 불가 또는 부분 데이터: 카드의 데이터 범위와 비용 산정 기준을 확인하세요. 일부 신호, 가격, 프로젝트 필드, 세션-턴 데이터 또는 Trace를 사용하려면 추가 수집이나 설정이 필요합니다. 누락된 값을 0으로 채우거나 부분합만 보고 데이터가 완전하다고 판단하지 마세요.
  • 오래된 데이터 또는 새로고침 실패: 새로고침 및 최신 상태 알림을 읽고, 다시 시도한 뒤 로그인 상태를 확인하세요. 새로고침에 실패하면 이전 데이터가 표시되고 있다는 사실이 명시됩니다. 운영 담당자에게 문의해 데이터 수집 및 권한을 확인하세요.
  • 작업 또는 링크 누락: 사용자, 적용 기간, Trace 보존 기간, 활성화된 클라이언트, 선택적 Trace 기능 및 잘림 알림을 확인하세요. 작업 흐름 필터와 상위 N개 제한으로 다른 작업이 숨겨질 수 있습니다. 공유 링크를 사용하려면 액세스 권한이 있어야 하고 전체 링크가 필요합니다.
  • 컨트롤이 보이지 않음: 클라이언트 활성화, 스키마, 역할, 기능 설정 및 수집된 이벤트에 따라 표시되는 내용이 달라집니다. 특히 기기 설정 및 상태를 보려면 권한이 필요하며, 채팅을 사용하려면 별도로 구성된 서비스와 읽기 전용 연결도 필요합니다.

전문적인 작업에 대해서는 설치, 운영, 아키텍처 및 API 계약을 참조하세요.
