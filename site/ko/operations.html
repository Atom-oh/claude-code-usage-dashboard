2026년 11월 10일 업데이트 · 소스 코드의 동작을 설명합니다. 설치된 리비전을 확인하세요.

트레이스 수집 확인 · Task Trace 안내

조직 SSO 연결

디스커버리/JWKS, 서명된 ID 토큰, authorization code 및 PKCE S256을 사용하는 기밀 OIDC 클라이언트에는 AUTH_MODE=oidc를 설정하세요. 콜백 주소 https://dashboard.example.com/auth/callback를 정확히 등록하세요.

공유 Cognito 사용자 풀은 별도의 앱 클라이언트, 콜백, 시크릿 및 역할 매핑을 사용해 여러 프로젝트를 제공할 수 있습니다. 애플리케이션별 그룹 할당은 ID 관리에서 처리해야 합니다. 고객 이메일, 도메인 및 풀 ID는 구성값이며 일반적인 애플리케이션 규칙이 아닙니다.

설정목적
APP_PUBLIC_URL경로, 쿼리 또는 프래그먼트가 없는 정확한 HTTPS 오리진입니다.
OIDC_ISSUER, OIDC_CLIENT_ID정확한 발급자 식별자와 전용 애플리케이션 클라이언트입니다.
OIDC_CLIENT_SECRET, SESSION_SECRET보호된 시크릿 참조를 통해 프로비저닝하세요. 복제본은 세션 키와 ID 구성을 공유해야 합니다.
OIDC_GROUPS_CLAIM최상위 서명 그룹 클레임입니다. Cognito의 경우 cognito:groups를, 그 외에는 공급자가 구성한 클레임을 사용합니다.
OIDC_SCOPES기본값은 openid profile입니다. 갱신 발급 요건을 포함해 구성된 공급자에 필요한 범위만 추가하세요.
OIDC_ROLE_GROUPSviewer, analyst 및 admin을 명시적 그룹 배열에 매핑하는 JSON입니다.
{
  "viewer": ["YOUR_VIEWER_GROUP"],
  "analyst": ["YOUR_EDITOR_GROUP"],
  "admin": ["YOUR_ADMIN_GROUP"]
}

UI의 편집자 역할은 analyst에 매핑됩니다. editor는 구성에서 역할 키로 사용할 수 없습니다. 매핑되지 않은 그룹은 로그인할 수 없습니다. 매핑된 역할 중 가장 높은 역할이 적용됩니다.

역할권한
viewer설치 전체 원격 측정 데이터를 읽을 수 있지만 Collector 관리와 채팅은 사용할 수 없습니다.
analyst / editor원격 측정 데이터를 읽고, 활성화된 채팅을 사용하고, 설치 프로그램을 다운로드하며, 소유한 디바이스를 관리할 수 있습니다.
admin분석가 권한에 설치 진단 권한이 추가됩니다.

Okta와 Keycloak은 적절한 범위와 서명된 그룹 클레임을 사용해 이 OIDC 계약을 제공할 수 있습니다. 실제 고객 공급자를 확인하세요. 일반 지원이 공급자 승인 테스트 완료를 뜻하지는 않습니다. 로그인은 사용자별 데이터 격리를 제공하지 않습니다.

공급자 설정 및 SSO 운영

로그인을 최대 30일간 유지

로그인 유지 기능은 선택 사항이며 기본적으로 비활성화되어 있습니다. 1시간의 인증 상한과 고정된 30일 로그인 한도는 다음과 같이 구성할 수 있습니다.

SESSION_MAX_AGE_SECONDS=3600
SESSION_REFRESH_MAX_AGE_SECONDS=2592000

일반적인 짧은 세션의 기본값은 900초이며 허용 범위는 300–3600초입니다. 갱신 수명은 0(비활성화) 또는 3600–2592000초입니다. 짧은 세션은 공급자 토큰 만료 시점의 제한도 받으므로, 1시간은 상한일 뿐 보장된 갱신 간격이 아닙니다.

갱신은 짧은 세션이 만료되기 전이나 만료된 후 요청이 들어올 때 수행되며, 백그라운드에서 매시간 실행되는 타이머 방식이 아닙니다. 30일 기한은 최초 로그인 시점부터 계산되며 연장되지 않습니다. 공급자가 이보다 일찍 세션을 종료할 수 있습니다.

  • 갱신 모드에는 재사용할 수 있고 회전되지 않는 refresh token, 현재 그룹을 포함한 새 서명 ID 토큰, client_secret_basic을 사용하는 교환/폐기가 필요합니다.
  • 이 모드에서는 회전만 지원하는 공급자를 사용할 수 없습니다. 갱신 응답에서 토큰이 회전되면 다시 로그인해야 합니다.
  • 암호화된 Secure/HttpOnly 쿠키를 사용하세요. 세션 API는 원시 ID 토큰을 반환하지 않습니다.
  • 로그아웃은 로컬 쿠키를 지우고 refresh token 폐기를 시도합니다. 공급자의 SSO 세션을 종료하거나, 복사된 단기 쿠키를 즉시 무효화하거나, 디바이스 토큰을 폐기하지는 않습니다.

갱신 세션 설계 및 제한

검토된 애플리케이션 리비전 배포

  1. 릴리스 PR을 병합하고, 깨끗한 빌드 컨텍스트에서 변경 불가능한 vX.Y.Z 태그를 배포하세요. 커밋을 기록하고 배포 런북의 사전 점검을 따르세요.
  2. AWS 자격 증명, 대상 클러스터, 기존 Terraform 입력값, 마이그레이션 상태 및 사용 가능한 롤백 이미지를 확인하세요.
  3. 대상 아키텍처용으로 빌드하고 변경 불가능한 이미지 태그/다이제스트를 게시하세요. 제공된 EKS 배포 대상은 arm64입니다.
  4. 필요한 경우 전체 인프라 계획을 검토하세요. 기존 설치 환경에서는 자동 부트스트랩 재시도가 아니라 호환성 확인과 명시적 업그레이드를 사용합니다.
  5. 롤아웃하고 준비 상태와 실제 이미지 다이제스트를 확인한 뒤 로그인, API 동작, 수집 최신성 및 대표 데이터를 검증하세요.

활성 상태 확인에는 /healthz를, 준비 상태 확인에는 /readyz를 사용하세요. 소스 코드 선언, 빌드 성공 및 정상 프로세스만으로는 ID 공급자의 정상 작동, 최신 원격 측정 데이터 또는 마이그레이션 적용을 확인할 수 없습니다.

문제가 발생한 경계부터 확인

증상우선 확인 항목
로그인 실패 또는 조기 종료정확한 오리진/콜백/발급자, 서명된 매핑 그룹, 공급자 만료 및 갱신 계약을 확인하세요. 토큰 값을 출력하지 마세요.
Collector 포트 사용 중선택한 릴리스의 소스 설치 프로그램을 사용하세요. 지원되는 macOS 마이그레이션 또는 기존 서비스 소유자의 수동 절차를 따르세요.
사용자 식별 불가 또는 분리됨의도한 --user-id, 전송된 ID 및 대시보드 필터를 확인하세요. 디바이스의 SSO 소유자가 원격 측정 데이터에 자동으로 연결되는 것은 아닙니다.
토큰은 발급됐지만 원격 측정 데이터 없음코딩 클라이언트를 다시 시작하고 작업을 생성한 뒤 로컬 서비스/내보내기 오류와 디바이스 수신을 확인하고 저장된 데이터를 검증하세요.
Codex 세부 정보에 대시 표시완료 코호트와 전체 기간의 완전성을 각각 확인하세요. 분모, 가격 또는 구성 요소가 누락된 경우 0으로 처리하면 안 됩니다.
비용 세부 정보가 느림쿼리 허용 상태, 필터 및 적용 해상도를 확인하세요. 용량을 변경하기 전에 비용/노력 프로필을 사용하고 대상 워크로드를 측정하세요.

Collector 제한 및 복구 · 비용 쿼리 동작

플랫폼별 운영 사전 요건

모든 호스팅 옵션에는 영구 ClickHouse 스키마와 정상 작동하는 OTel 파이프라인이 필요합니다. ECS와 EC2에는 별도로 작성한 서비스/시크릿/스토리지 구성이 필요하며, 제공된 Terraform은 기존 EKS 환경을 대상으로 합니다. Lambda에는 애플리케이션 런타임 조정과 외부 데이터베이스/Collector 서비스가 필요합니다.

배포 옵션 및 지원 범위 · 스키마 초기화 · Collector 설정

문서 배포

이 문서는 site/에 있는 정적 HTML입니다. Pages 워크플로는 main에 병합된 변경 사항이 있을 때 해당 디렉터리를 업로드합니다. 문서만 릴리스하는 경우 번들러 빌드나 애플리케이션/EKS 롤아웃은 없습니다.

전체 절차는 소스에 연결된 런북을 사용하세요. 웹사이트는 지원되는 동작을 요약하며 특정 고객 설치 환경의 구성을 보증하지 않습니다.

Trace 경로 확인

새 상호작용과 예상되는 원격 측정 ID, 클라이언트 및 시간 버킷부터 확인하세요. 사용량 합계와 Trace 사용 가능 여부는 서로 다른 신호에서 나오므로 로그 내보내기가 성공했다고 트레이스가 전송된 것은 아닙니다.

  1. 현재 디바이스 패키지 또는 조직에서 관리하는 설정에 트레이스 내보내기가 활성화되어 있는지 확인한 다음 코딩 클라이언트를 다시 시작하세요. 클라이언트 구성 참조를 확인하세요.
  2. 로컬 Collector의 서비스와 트레이스 내보내기에서 전송 실패를 확인하세요. 인증된 수집, 중앙 트레이스 파이프라인 및 저장된 otel_traces 레코드까지 차례로 확인하세요. 디바이스 수신과 프로세스 상태는 각각 해당 단계만 확인합니다.
  3. 사용자 세부 정보에서 작업 시작 시각이 포함된 추세 버킷을 선택하세요. 의도한 ID와 필터를 확인하세요. 지원되는 트레이스 작업은 90일간 보관됩니다.
  4. Codex 진단의 경우 전체 인사이트 프로필을 사용해 Analytics의 Trace 탭을 확인하세요. 비용/노력, 도구 및 성능 프로필은 트레이스 쿼리를 생략합니다.
증상확인할 항목
사용량은 있지만 작업이 표시되지 않음트레이스 구성, 재시작 시각, 전송된 ID, 작업 시작 버킷 및 보존 기간을 확인하세요. 과거 사용량은 트레이스로 소급 입력되지 않습니다.
Codex 완료 항목이 작업에 포함되지 않음추적된 턴에는 대화 ID와 고유 턴 ID가 필요합니다. 적격 턴이 없는 완료 항목은 연결되지 않습니다. 샘플링 스팬이 없는 연결 완료 항목은 비용 구간에서 누락될 수 있습니다.
Codex 하위 에이전트 수를 확인할 수 없음현재 작업 뷰에는 기본 레인만 있으며, 관련 없는 스팬으로 하위 에이전트 수를 추정하지 않습니다.
세부 정보가 많을 때 합계가 생략됨truncated와 span_total을 확인하세요. 작업 세부 정보는 5,000개 스팬으로 제한됩니다. 별도의 진단 미리보기는 트레이스 50개, 트레이스당 스팬 200개를 사용합니다.
모델 필터를 적용하면 Codex Trace가 사라짐모델 속성이 있는 스팬만 해당 필터와 일치합니다. 다른 진단 스팬을 확인하려면 필터를 지우세요.
