Organizer-prepared workshop environments have a separate configured collection path. Do not overlay the device package onto an already prepared Collector without migration.

Data boundaries · Codex observability

Client, backend and session channel

Collection and API routing identify the emitting client. Provider provenance and model evidence inform backend classification; a model identifier by itself cannot identify the client.

The Claude session-channel classifier distinguishes bedrock, enterprise and unknown. Observed Bedrock model evidence and organization/model fallback rules apply at session scope. This classification is not the dashboard user's SSO role.

Regional/geographic Bedrock model identifiers and bare provider IDs are normalized by the pricing/backend logic. Preserve unsupported scopes and unknown prices rather than assuming every model ID has a price. Codex has no enterprise A/B row.

Backend pricing decision

Reduce query work without changing totals

  • view=cost selects the shared overview's bounded cost profile, omitting unused diagnostics.
  • profile=effort selects Codex log-only detail and skips unrelated metric/trace queries.
  • Codex log aggregation compacts full-identity events in ClickHouse before transfer. Aggregate-family limits remain visible.
  • Single-flight caching and bounded admission share repeated work while retaining filter identity, deadlines and overload errors.

These mechanisms reduce work; they do not establish a capacity guarantee for 140 concurrent users. Measure representative filter diversity, cold-cache traffic, ingestion and query latency on the target installation.

Dashboard access and device access

OIDC verifies signed identity and maps explicit group values to viewer, analyst or admin. Authorized viewers can read installation-wide telemetry; this is not per-employee row isolation.

Device tokens grant ingestion only. They are separately owned, expired and revoked. Telemetry attribution is client-provided; neither an SSO session nor token ownership automatically certifies a telemetry email.

PII masking is a display feature, not API access control. Collection filters remove known content fields but cannot detect arbitrary secrets placed in otherwise supported metadata.

Deployment boundaries

The dashboard image contains the web UI and API. ClickHouse, its schema and the OTel Collector are separate components on every platform. The current Compose file omits the Collector; EKS Terraform reuses existing cluster dependencies. ECS/EC2 need platform configuration, and Lambda requires runtime adaptation.

Required components · Compare hosting options

The supplied Terraform targets an existing EKS environment. The application container communicates with ClickHouse; local Compose is available for development. ECS, Fargate and other runtimes need their own reviewed infrastructure, credentials, networking, probes and persistence configuration.

Schema lifecycle, application images, Collector policies and runtime options have independent deployment state. A successful build or Terraform validation does not prove a live rollout or migration.
