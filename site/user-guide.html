02. Explain cost changes and token efficiency

Begin with a comparable period and cost basis. Move from the total to a model or user, then use token economics and traced work to understand the observed change.

  1. Fix the comparison scope

    Choose a client, backend and time period. Read the displayed effective bounds and compare equal-length periods in Trends. In Cost, distinguish reported Claude spend, estimated non-Anthropic Claude or Codex spend, and mixed or partial subtotals. A missing price remains unavailable; no displayed cost is an invoice.

  2. Find the model or user contribution

    Use model and user breakdowns to locate the change. Where supported, select a model to inspect its users, or select a user for the matching-period detail. Model user shares use the known model cost subtotal as their denominator. A share of known cost does not account for unpriced observations.

  1. Read the six-factor cost equation

    Open Productivity. When session-turn data is ready, 비용 방정식 links active users, sessions per user, turns per session, requests per turn, tokens per request and token price. First read how many sessions matched the calculation and which observations were excluded. The equation describes that eligible population.

  2. Separate growth from per-request changes

    Use 드라이버 분해 to read each factor’s signed contribution to the observed cost difference. Compare the prior and current total with the driver sum. More users or sessions can increase spend even when tokens per request or unit price fall. The screen’s 낭비 grouping is an accounting label for selected factors, not proof that a person or request was wasteful.

  1. Read unit costs, tokens and cache with their denominators

    Inspect cost per user/session/request and tokens per request, then compare model economics and available cache or reasoning shares. Read each metric’s help and coverage: observed-token subtotals are not interchangeable with complete components used for ratios. In unit-cost charts, a dashed segment connects observed endpoints across an unavailable interval; it is not a measured cost for the gap.

  2. Return to the work before making a change

    Open the relevant user and sort their traced tasks by cost. Compare model changes, repeated context, cache observations, tool activity and recorded errors or retries. These observations can guide a review of prompts or workflows, but they do not establish causal savings, code quality or employee productivity. Re-check the same scope after any real workflow change.

Total cost rises, unit cost stays similar

Inspect active users, sessions and request counts first. More observed activity can explain a larger total without a worse per-unit result.

Tokens per request or model price changes

Inspect model mix, effort/speed tiers where available, context and cache composition. Compare matching populations and then open representative tasks.

03. Inspect tools, MCP, Skills and permissions

Tool activity helps explain how work was carried out. Separate a tool call, its permission decision, its result and the session’s loaded environment before comparing counts.

  1. Start with Usage and the source you need

    In shared Usage, compare token composition and available per-client tool activity. Keep client and period fixed. For Claude-specific tool, MCP and Skill sections, select Claude Code and Claude 상세 보기. Signals that a client does not provide remain unavailable rather than zero.

  2. Read calls and outcomes together

    Compare tool names, counts, failures and timing where collected. Distinguish common operations such as reading/searching, editing, shell execution and agent calls. A larger call count is not automatically better or worse; inspect the task and whether the same operation repeats. Permission approval and successful execution are separate observations.

  1. Inspect MCP by server and operation

    Read the observed MCP servers and tool names. A connected server in session environment shows a connection observation; it does not prove every advertised tool ran. A failed status is a signal to inspect, not a complete explanation for cost or task failure. Missing MCP events can leave this view empty.

  2. Distinguish Skill use from loaded plugins

    Inspect the available Skill invocation and attribution tables. Review loaded plugin counts and related session observations separately. Loading a plugin is not the same as executing every Skill or command it contains, and attributed Skill costs are not an extra amount to add to total spend.

  1. Check permissions and waits

    Use the available permission-mode, approval-source and tool-result sections in Usage and Productivity. Automatic approvals are not a code acceptance rate. Compare denied decisions, execution errors and permission waits as separate stages, and read the stated population of each table.

  2. Open the relevant task

    In Users, open the user and matching period, then inspect available Task Trace tool and wait spans. Read tool metadata, observed duration and parent/agent placement. Use the model calls and context views to relate tool activity to LLM activity. Raw commands, prompts and paths are not exposed in the span panel.

When a table is empty: check the client, time, filter applicability and collection version. A missing signal does not establish that the tool was never used. Codex diagnostic metrics and traces remain separate from completion-log usage totals.

Claude detail instead may offer bedrock and enterprise inferred session channels; these are not client identities, authorization groups or a Codex comparison. Time, refresh and charts

Choose a day preset, 이번 달 (this month), or 기간 직접 선택 (choose a period). In the picker, 날짜 uses UTC calendar days; 날짜·시간 accepts local browser dates and times to the second, with the end exclusive. Choose 적용 to apply. Date presets and buckets use UTC; chart labels, precise times and exports display in your browser's time zone. Requested and effective periods can differ because data is grouped and recent ingestion is allowed time to arrive. Read the effective-period notice before comparing.

Use 지금 새로고침 for an immediate refresh or choose an automatic interval, including off. During a background refresh the previous result may remain visible; a failure explicitly says so. When a new period is loading or fails, do not treat old data as the new period. Shared Cost and Trends offer 추이 해상도 (trend resolution): up to ten-minute buckets for periods of at most a day, with coarser options for longer periods.

Hover a chart to read values and use the legend to identify series; some legends let you focus a series. On supported time-series charts, drag across a time interval to change the whole page's period. Clear the custom-period chip with its × or choose a preset to reset. Categorical charts do not zoom. In user detail, a point click can select a single time bucket for the task list; a drag changes the page period. Chart actions can be unavailable while a result is stale.

Tables, exports and privacy

Where column headings offer sorting, click a heading to change order. Some tables have their own search or other selectors; the top filter bar is not a universal search of every table. Tables show the returned rows rather than providing a general page control. Collector devices have a separate 기기 더 보기 (load more) control. Where a CSV button appears, it exports the displayed columns and sorted rows, not an automatic export of every dashboard result. It is disabled for empty or stale results. Some charts offer their own CSV download. Some shared tables initially show 20 rows when there are more; use 전체 …행 보기 to expand it, and CSV follows the visible rows. Model-cost trend charts offer 누적/기본 display modes, a data table and selectable legend series; use 모두 보기 to restore them. Horizontal scrolling may be needed for wide tables.

Masking can hide parts of identities on screen and in supported exports, but it is not an access-control boundary. User detail and task information can still be sensitive. Share only with authorized recipients, check the content and range first, and never put collector tokens or personal/customer data in screenshots, links or public material.

What a number means

—, unavailable (미수집 or 미산정) and an empty result are not the same as an observed zero. A partial label (부분합) means a known subtotal, not a complete total. A positive total does not prove complete telemetry. Loading, request errors, a shortened range and stale refresh warnings each need separate attention. Hover the help icon and read the card subtitle for its population and denominator.

For Anthropic models, Claude detail spend remains report-based and calculated token-price values are opt-in diagnostics. Shared overview may fill missing reports with a separately labeled estimate. Claude non-Anthropic models and Codex use AWS list-price estimates. Mixed totals retain their bases and unknown prices. None is an invoice or guaranteed billing bound. Observed token subtotals may omit components; ratios require their complete denominators. Codex runtime metrics and traces are diagnostic feeds and must not be added to completion-log usage or cost.

Account, help and release notes

In organization-login mode the sidebar or mobile menu shows your account name (masked when masking is enabled) and role: viewer (조회), analyst (분석) or administrator (관리자). Use 로그아웃 to end the browser session. If a session expires, sign in again; access and telemetry visibility are controlled by your organization's configuration. Other authentication modes can look different. Organization identity, group membership and MFA are managed by the identity provider.

사용설명서 opens public documentation. 변경 내역 opens bundled release notes, with version summaries and links to relevant features, releases and the technical changelog. A dot can indicate a release this browser has not opened. Release notes describe changes; this guide describes the product as a whole.

Recurring workflows

QuestionSteps
Why did spend increase?Choose client and period; open Trends for the previous-period comparison and drag the increase. In Cost, compare model, Effort and user breakdowns with their cost bases and partial labels. Select a model or user for its matching-period detail. Check Reliability and collection changes before attributing a cause.
Is data missing?Check the client, period, filters, freshness and error notices. Compare observed-token and cost coverage in Overview and Analytics. If authorized, check device receipt and Installation status; otherwise ask an operator. Run a new client session and refresh. Receipt or a positive total does not prove completeness.
Which work was expensive?In Cost, inspect model and user breakdowns. Open Users, select an identified user, then sort the task list by cost. Open a row for lanes, calls, cost band and context. Account for partial trace collection, the top-20 and Claude candidate limits, and the cost basis.
Compare clients and modelsSelect all enabled clients, choose the same range and use Overview, Usage and Cost. Read each client's backend, model, observed-token coverage and cost basis. Do not infer client from model name or treat inferred Claude channels as clients. Select a model in Cost for its users.
Onboard or revoke a deviceWith the required permission and configured ingestion, use Collector setup to register a named device, securely copy its token when displayed, install and verify a new session. To stop collection, select the device and confirm revocation. See Collector setup.

Troubleshooting

  • No rows: Check source, time and filters; try a new client session. An empty period can mean no matching observations, not zero organization-wide use.
  • Unavailable or partial: Check the card's coverage and cost basis. Some signals, prices, project fields, session-turn data or traces require additional collection or setup. Do not fill gaps with zero or infer completeness from a subtotal.
  • Old or failing data: Read refresh and freshness warnings, retry and check your login. If a refresh fails, retained data is explicitly previous. Ask an operator to investigate collection and permissions.
  • Missing task or link: Check the user, effective period, trace retention, enabled client, optional tracing and truncation notices. Workflow filtering and top-N bounds can hide other tasks. A share link requires access and the complete link.
  • Missing control: Client enablement, schema, role, feature configuration and collected events affect what is shown. In particular, device setup and status require permission, and chat additionally requires its own configured service and read-only connection.

For specialist work, see installation, operations, architecture and API contracts.
